# 需求说明

版本：3.4｜日期：2026-11-04｜状态：当前授权实施，验证证据独立登记

## 阅读背景与必要概念

本文面向需求阅读者和审阅者，说明 Atoms Studio 本阶段应提供什么，以及哪些行为仍只是目标。使用者在工作台提交文字，看到计划并确认执行；系统随后取得页面结构和 HTML 文档，保存后供预览与历史恢复。HTML 是浏览器呈现页面的文字格式，计划卡是展示摘要、步骤和文件说明并提供确认、调整及复制的界面区域。

项目是一次工作空间的持久记录；消息保存需求、计划和系统备注；历史版本保存一次构建的完整 HTML。记录的 id 是数据库标识，version_no 是同一项目内的版本序号；项目字段 current_version 保存当前使用的版本序号，不是历史版本的 id。例如历史记录 id 为 201、version_no 为 1 时，恢复它会把 current_version 改成 1，而不是 201。这些数字是文档示例，不是预先存在的数据。

mock 是用预置成功结果或受控失败替代外部调用；串行是前一项及其子请求全部结束后再开始下一项。当前产品采用邮箱/密码登录与按用户隔离的数据、操作串行；AI 输出已接入真实供应商（阿里百炼主选、Ark/智谱备选），示例输入短路返回固定结果，供应商不可用时回退 mock。登录认证与多用户数据隔离已作为 Phase 17 实施（见 [roadmap](roadmap.md)）：`/studio/*` 要求登录并按 `user_id` 过滤，跨用户访问返回 404。未验证子情景不写成通过。


## 1. 产品目标和边界

Atoms Studio 是登录用户各自数据上下文中的对话式应用工作台。本阶段验证主流程：输入需求 → 计划 → 确认执行 → 结构与 HTML 生成 → 保存项目、消息和版本 → 查看与恢复版本。计划、结构与 HTML 由真实 AI 生成，四个示例输入命中时短路返回预置结果。

**认证边界（Phase 17 已实施，2026-11-04）**：`/auth/*`（注册、登录、当前用户、登出）与 `/health` 公开；`/studio/*` 全部要求 `Authorization: Bearer <JWT>`，未登录返回 401 `AUTH_REQUIRED`。令牌有效期 7 天、无 refresh token；`APP_AUTH_SECRET` 缺失时应用启动失败。仅邮箱/密码登录，不做 OAuth；不提供用户管理后台、角色管理或租户隔离产品模块。数据按登录用户 `user_id` 归属，所有查询强制过滤；跨用户访问统一返回 404 `RESOURCE_NOT_FOUND`，不返回 403，避免泄露资源存在性。存量共享数据迁移到幂等 `legacy` 用户，不删除、不置空。不考虑同时操作、并发锁和任务队列；每项操作成功或失败结束后才允许下一项。

保留现有TypeScript前端和Python后端，不进行Java或其他语言迁移。本轮授权实施现有技术栈上的最小闭环；Phase 17 新增数据归属字段与索引，是首次生产表结构变更，已在本地数据库执行迁移 `c2d3e4f5a6b7`，生产部署前仍需单独评审与回填演练。

## 3. 操作要求

一项用户操作包括它引发的全部子请求。例如首次提交依次建项目、保存需求、取得计划；确认执行依次取得结构、取得HTML并保存。子请求逐个等待。执行中主导航、新建/选项目/删除、输入、示例提示、提交、确认/调整/复制、配置、预览操作及版本选择不可开始下一项。成功和失败均解除执行中状态。不设置自动排队、后台并发、锁或多标签协调。

浏览器强制关闭/刷新不属于可禁用的产品按钮。本阶段只要求提交成功的数据可重新读取，不承诺未提交草稿或执行中任务恢复。

## 4. 数据与 AI 输出

项目、消息、版本为三种业务实体。消息role表示发言方，不是使用者权限。HTML存入版本快照，current_version指示当前序号。Phase 17 起，Studio 路由从 JWT 取得当前登录用户，新记录写入其 `user_id`，所有读写查询按 `user_id` 强制过滤；请求体中的 `user_id` 不参与归属计算，无法覆盖当前会话。执行记录 `executions` 同样归属用户，停止执行时校验归属。

当输入与四个示例文本完全一致时，系统短路返回预置计划、结构和 HTML（如「记录饮水」返回「演示计划一」及「模拟第一版」HTML），不调用真实 AI；其他输入走真实供应商。第二轮输入（如「增加备注」）在同项目追加版本；请求包含本轮requirement、plan_summary和outline，不包含历史列表或先前HTML，模型不依赖历史上下文理解前版功能。

真实 AI 已接入：供应商为 OpenAI 兼容接口，模型集中配置在 `MODEL_PROFILES`；阿里百炼使用工作区专属 MaaS 域名与 `qwen3.8-flash`，火山方舟/智谱作为备选，失败时可回退 mock。**已实测确认（2026-11-04）**：百炼工作区域名返回非空正文（7.63s）；公共域名 `dashscope.aliyuncs.com` 同模型返回 403 `AccessDenied.Unpurchased`，两种域名权限不通用；方舟 `deepseek-v4-1-flash-economy-261017` 返回 200、2.08s、`finish_reason=stop`，但默认开启 thinking，`max_tokens` 过小（如 32）会导致 `content` 为空；401/403 立即降级不重试，全部失败抛 `AllProvidersFailedError`。

## 5. 当前规则与限制

| 事项 | 当前实现 |
|---|---|
| 重试 | 重新执行真实失败动作，闭包保留已成功阶段；未确认的建项目/存需求先经读接口核对，避免盲目重复写入 |
| 批准状态 | 构建成功与计划meta.approved/version_id同事务提交；重复构建返回已保存版本 |
| 多张计划调整 | 使用被点击卡片meta.requirement，不取最后一条需求 |
| 需求长度 | 完整保存与传递，不截断2000字符；项目名称仍限制80字符 |
| 列表容量 | 维持项目最近60条、消息最早400条，不新增分页；超容量不保证读回全部历史消息 |
| 手机入口 | 最小项目抽屉提供打开/关闭按钮，执行中禁用 |
| 错误协议 | **当前实现（Phase 16 已完成，2026-11-04）**：字段无效422、不存在404、提供者/结构无效502、数据库提交失败500，统一响应 `ErrorResponse{code, message, details?}`；`code` 为 `DOMAIN_REASON`、`message` 为中文可读句子，未保留 `detail` 双写；`request_id` 已决策暂缓 |
| 版本部分成功 | 恢复成功立即同步摘要并清空旧预览；读取失败明确告知已恢复，重试仅读取 |

不提供跨标签协调和后台任务恢复。响应丢失后的核对依赖可见记录容量，超过400消息时不能承诺需求完全去重；这是既有容量限制，不增加幂等字段或服务器锁。

## 6. 验证与追溯

仅两层：单元测试对象为类或页面，所有外部调用mock；集成测试真实模块、业务接口和测试数据库协作，AI边界仍模拟。详见[测试策略](测试策略与规范.md)、[覆盖索引](测试用例与覆盖矩阵.md)及各模块文档。

范围为3业务页面、26类交互目标（原24类加手机抽屉打开/关闭）、11业务接口。已建立自动化用例合计228条：前端56条（单元21、界面集成35）、后端172条（单元113、接口集成59）；后端数量以 2026-11-04 Phase 17 后 `pytest --collect-only` 收集结果为准，不代表本轮全部执行，执行统计以[测试执行记录](测试执行记录.md)为准，不等于原设计所有子情景已通过。

后端接口集成在进程内调用测试宿主与真实 PostgreSQL、使用独立 schema，仅模拟 AI 输出；与界面集成同属「集成」层，不新增层级。后端测试设计见[后端测试设计与用例](后端测试设计与用例.md)。

## 7. 实施对应

前端Index协调实际业务步骤，StudioOperation集中管理busy、错误和重试；SDK接口形状保持不变。后端Studio业务路由使用既有三实体；AI 调用经 `services/aihub.py` 走 OpenAI 兼容供应商（阿里百炼/Ark/智谱），示例命中与供应商不可用时回退 MockOutputProvider；模型集中配置在 `MODEL_PROFILES`，不按表单临时传模型。没有为形式创建一套控制器/仓储目录。产品内「部署」与「Cloud」页面仍是占位说明；平台自身已用 Fly.io 部署，不因此改变产品页面状态。

## 术语表

- mock：预置成功结果或受控失败代替外部调用。
- 示例提示按钮（旧称示例芯片）：点击填入文字但不自动提交。
- 计划卡：展示计划并提供确认、调整、复制的区域。
- 抽屉：从边缘展开并可收起的面板，手机已提供项目抽屉。
- 快照：完整HTML版本记录；项目当前使用的版本序号决定显示哪个版本。
- 串行：前项成功或失败结束后才开始下一项。
- entity：具有持久身份的业务实体，本项目为项目、消息、版本。
- 后端单元测试：只检查一个后端函数或职责对象，数据库、HTTP 与提供者全部替身，不连接真实服务。
- 接口集成测试：进程内调用真实后端与真实数据库、只模拟 AI 边界的测试，属「集成」层的一个作用域。
- 设计映射：文档中需求、对象与用例的对应关系，不表示测试已建立或已执行。
