## 1. 实际命令与运行环境

单元测试：`node node_modules/vitest/vitest.mjs run`（等价 `pnpm test`），配置 `app/frontend/vitest.config.ts`，用例 `app/frontend/tests/studio.unit.test.tsx`，全局替身与清理在 `tests/setup.ts`。

集成测试：`node node_modules/@playwright/test/cli.js test --config=tests/studio.config.ts`（等价 `pnpm test:integration`），单 worker，35 个集成测试，JSON 证据位于 `app/frontend/tests/results.json`（已加入 .gitignore）。

两层各有一个入口：Vitest 只采集 `tests/**/*.test.{ts,tsx}`，Playwright 只采集 `tests/studio.integration.spec.ts`，不互相重复执行。

测试宿主testing/studio_app.py只在studio_test_t1命名空间建立并重置三张业务表。/__test/reset逐例清空隔离表、重置序号和故障状态，不触碰public生产数据。测试HTTP请求访问真实Studio路由、SQLAlchemy和PostgreSQL；AI输出固定mock。UI集成页面通过真实SDK访问测试宿主；单元测试用 jsdom 挂载组件并替身外部调用，不访问业务服务。

## 4. 启动与修正历史

- 初次启动：测试服务相对目录错误，未执行产品用例；改为明确cwd。
- 首次完整尝试：18通过、38失败。前半页面测试缺匹配Chromium可执行文件；容量用例60秒超时；构建后错误等待空输入提交按钮enabled；静态单元JSX被测试运行器转为非React对象。
- 修正：安装Chromium，配置240秒用例上限；用输入框可编辑判断busy结束；显式使用tsconfig.app.json的react-jsx编译设置。保留初次结果，不抹去失败。

- 第二次完整运行：36通过、20失败、0跳过。33项集成通过；导航初始化用浏览器requestfinished事件判断顺序的断言失败，窄屏定位器匹配隐藏侧栏及抽屉两个实例。18项静态页面单元仍被JSX转换成非React对象阻断，显式tsconfig未解决。相同原因达到修正尝试上限，保留当前实现与证据，不继续盲目重跑。

- 第三次（2026-11-01）：确认 Playwright 无法承载 React 组件单元后，新增 Vitest 3.2.7 + jsdom + React Testing Library（与应用同一 vite 5 版本线，避免 peer 冲突），迁移 18 条组件用例并保留 3 条 StudioOperation 用例，共 21 条全部通过；同时接入 @vitest/coverage-v8 产出真实覆盖率。旧 Playwright 单元文件 `tests/studio.unit.spec.ts` 删除，Playwright 入口只保留集成测试。
