# AI 额度使用记录

版本：1.0｜日期：2026-11-04｜状态：现行记账台账，任何真实 AI 调用前后必须更新

## 用途

本文是 Atoms Studio 阿里百炼与火山方舟免费额度的**唯一记账来源**。凡调用这两家真实 API（含页面生成、冒烟验证、端到端测试、修复重发），都必须在调用前登记预算、调用后登记实际 usage；额度用尽即不可再调用，只能使用 mock 或单元测试。

本文只记录额度与调用事实，不替代 [roadmap](roadmap.md) 的功能规划，也不替代 [测试执行记录](测试执行记录.md) 的测试结论。

## 与产品内统计的关系（2026-11-04 新增）

产品内「AI 用量」统计（设置页 + `GET /api/v1/user/ai-usage`）读取应用落库的 `ai_usage_records`：每次调用一行，记录 `user_id` / `build_id` / `stage` / `provider` 与供应商返回的 prompt / completion / reasoning tokens；模拟输出记 NULL，不伪造数字。聚合口径为：

- **今日**：服务器本地自然日 00:00 至当前。
- **近 7 天**：含今日在内共 7 个自然日。
- **累计**：该用户全部记录。

两者不可直接相减，也不应互相替代：

- 本台账登记的是**供应商免费额度余量**（基线 919,000 / 499,632），覆盖真实调用、冒烟与 e2e，是预算约束。
- 产品内统计只覆盖**经应用调用链产生并成功落库的调用**，不含手工冒烟、脚本直连、失败未产生 usage 的请求，也不含供应商侧的计费误差。
- 数字不一致时，以本台账为「额度事实」，以产品内统计为「应用行为事实」；排查先核对调用时间与 provider。
- 产品内统计**不能替代**本台账更新：真实调用仍须按下方记账规则登记。

## 记账规则

1. **调用前先估算并写明理由**：任何真实调用前，在本表新增一行或书面说明预计阶段与预估 tokens（含重试余量），说明为什么需要真实调用而非 mock。
2. **调用后立即登记 usage 明细**：记录每家供应商、每个阶段的 usage；能拿到 prompt/completion 拆分时必须分开填写，拿不到则写「—（未拆分）」并在备注说明来源。
3. **单轮 e2e 预算上限 20,000 tokens**：单轮端到端（plan + outline + html）合计超过 20,000 tokens 时停止并复盘，不得无上限重试。
4. **重试与降级分别记录**：同一请求的重发、修复重发、供应商降级都要单独登记，不得合并进原始阶段的小计；降级到备用供应商时，原供应商记失败原因、备用供应商记实际用量。
5. **失败也要记**：401/403 等未产生 token 的调用记 0 并注明失败原因；不得因为失败就不登记。
6. **余额低于 10% 停止**：任一家剩余额度低于其基线 10%（百炼低于约 91,900、方舟低于约 49,963）时，立即停止该家真实调用并提示用户确认，是否继续只能由用户决定。

## 术语表

- 基线：2026-11-04 用户提供的余额，作为本表累计的起点。
- usage：供应商返回的 token 用量；本文用「小计」表示单次调用或单轮合计消耗。
- 小计：单行记录本次实际消耗的 tokens 总数。
- 累计已用：自基线以来累计消耗（本表当前口径为两家分别累计）。
- 降级：主供应商失败后切换到备用供应商的调用行为，需独立记账。
- 单轮 e2e：一次完整端到端流程（plan、outline、html）的合计调用。
