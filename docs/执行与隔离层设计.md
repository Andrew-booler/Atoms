# 执行与隔离层设计

版本：1.0｜日期：2026-11-01｜Phase 1 实施

## 1. 目标

把 Output Provider 产出的单文件 HTML 放进隔离沙箱运行，返回预览 URL 供前端 iframe 加载，避免直接 `srcDoc` 注入带来的 XSS 与同源风险。

- HTML 写入隔离工作区目录，由 Docker 容器（`nginx:alpine`）以只读方式挂载并提供静态服务。
- 容器有严格的安全边界（只读根文件系统、丢弃所有能力、CPU/内存/PID 限制、端口仅绑 `127.0.0.1`）。
- 容器有空闲超时，到时自动停止并删除；后端有后台回收器兜底清理。
- 可对已保存版本重新运行预览，可手动停止。
- Docker 不可用时，artifact 仍保存但 `preview_url` 为空，前端降级到 `srcDoc`。

## 2. 架构

```
artifact 路由
  ├─ 保存 artifact_html 到 studio_versions
  └─ ExecutionService.run_html(html, version_id)
       ├─ 分配端口（socket bind 127.0.0.1:0）
       ├─ 写工作区 <SANDBOX_ROOT>/<uuid>/index.html
       ├─ docker run -d --read-only --cap-drop=ALL ... nginx:alpine
       └─ 写 Execution 记录（status=running, expires_at=now+timeout）

前端 ArtifactPreview
  ├─ preview_url 存在 → <iframe src={preview_url}>
  └─ 否则 → <iframe srcDoc={artifact_html}>（降级）

后台回收器（lifespan 启动）
  ├─ 启动时清理所有 atoms-sandbox- 前缀残留容器
  └─ 每 60s 扫描 expires_at < now 的 running 执行，docker stop + 标 expired
```

## 3. 数据模型

`executions` 表（见 `models/execution.py`）：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | int PK | 自增 |
| version_id | int | 关联的 studio_versions.id |
| container_id | str(128) nullable | Docker 容器 ID |
| port | int | 宿主端口 |
| status | str(20) | running / stopped / failed / expired |
| preview_url | str(255) | 预览地址 |
| started_at | datetime | 启动时间 |
| expires_at | datetime | 过期时间 |

迁移：`alembic/versions/a1f2e3d4c5b6_add_executions.py`。

## 4. 执行服务

`services/execution.py::ExecutionService`，每个实例绑定一个 `AsyncSession`。

### 核心方法

| 方法 | 说明 |
|---|---|
| `run_html(html, version_id) -> Execution` | 分配端口、写工作区、docker run、写 DB |
| `stop(execution_id) -> Execution \| None` | docker stop、清工作区、标 stopped |
| `cleanup_expired() -> int` | 扫描过期 running 执行并停止 |
| `cleanup_orphan_containers()` | 启动时清理 `atoms-sandbox-` 前缀残留容器 |
| `is_docker_available() -> bool` | `docker info` 检查 |
| `ensure_image()` | 镜像不存在则拉取，结果缓存 60s |

### Docker run 命令

```
docker run -d --name atoms-sandbox-<uuid> \
  --rm --read-only \
  --cap-drop=ALL --security-opt=no-new-privileges \
  --cpus=0.5 --memory=128m --pids-limit=64 \
  --network=bridge -p 127.0.0.1:<port>:80 \
  -v <workspace>:/usr/share/nginx/html:ro \
  -v <sandbox_root>/nginx.conf:/etc/nginx/nginx.conf:ro \
  --tmpfs /tmp:rw,noexec,size=16m \
  --entrypoint nginx \
  nginx:alpine -g "daemon off;"
```

`nginx:alpine` 官方镜像默认 `user nginx;`，启动时 root 主进程会 `chown` 临时目录到 uid 101；在 `--cap-drop=ALL` 下缺少 `CAP_CHOWN` 会启动即崩溃。因此挂载自定义 `nginx.conf`（worker 以 `user root;` 运行、`pid` 与临时目录改写进 `/tmp`），并用 `--entrypoint nginx` 绕过官方入口脚本直接启动，既保持只读根文件系统，又避免降权所需的 capabilities。

### 端口分配与冲突重试

`_allocate_port()` 通过 `socket.bind(("127.0.0.1", 0))` 取空闲端口后释放。若 `docker run` 报端口占用，重试最多 3 次换端口。

### 工作区

路径：`<SANDBOX_ROOT>/<uuid>/index.html`，权限 `0o644`。容器以 `:ro` 挂载，容器内不可改。停止时删除工作区。

## 5. API 变更

### 新增字段

`BuildResponse` 增加 `preview_url: Optional[str]`。

### 新增接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/studio/versions/{version_id}/run` | 对已保存版本启动沙箱预览，返回 `ExecutionResponse` |
| DELETE | `/api/v1/studio/executions/{execution_id}` | 停止并清理执行 |

### artifact 路由行为

存库后调用 `_try_run_preview(db, html, version_id)`：
- 成功 → 返回 `preview_url`
- Docker 不可用 / 失败 → 记录 warning，返回 `None`（不影响 artifact 已存库）

## 6. 配置项

全部通过环境变量读取，默认值写在 `ExecutionService` 中：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `SANDBOX_ROOT` | `tempdir/atoms_sandbox` | 工作区根目录 |
| `SANDBOX_IMAGE` | `nginx:alpine` | 沙箱镜像 |
| `SANDBOX_IDLE_TIMEOUT` | `600` | 空闲超时（秒） |
| `SANDBOX_HOST` | `127.0.0.1` | 预览 URL 的 host |
| `SANDBOX_CPU` | `0.5` | CPU 限制 |
| `SANDBOX_MEMORY` | `128m` | 内存限制 |
| `SANDBOX_PIDS_LIMIT` | `64` | PID 限制 |
| `SANDBOX_CLEANUP_INTERVAL` | `60` | 回收器扫描间隔（秒） |

## 7. 安全边界

- 工作区 `:ro` 只读挂载
- 容器根文件系统 `--read-only`
- `--cap-drop=ALL` 丢弃所有 Linux capabilities
- `--security-opt=no-new-privileges` 禁止提权
- 端口仅绑定 `127.0.0.1`，不对外暴露
- CPU / 内存 / PID 限制防止资源耗尽
- `--tmpfs` 给 nginx 必要的可写目录（`/tmp`，存放 `nginx.pid` 与临时文件），`noexec` 禁止执行
- 容器名 `atoms-sandbox-` 前缀，便于识别与批量清理
- 每次执行独立容器与端口，天然隔离

## 8. 失败处理

| 场景 | 行为 |
|---|---|
| Docker 未安装/未启动 | `is_docker_available()` 返回 False → artifact 返回 `preview_url=None`，前端降级 `srcDoc` |
| 镜像拉取失败 | `ensure_image()` 抛 `DockerNotAvailableError` → 同上，结果缓存 60s 避免反复超时 |
| 端口被占用 | 重试最多 3 次换端口 |
| `docker run` 其他错误 | 标 `failed`（当前实现抛异常由调用方处理，artifact 路由捕获后返回 `None`） |
| 工作区清理失败 | 记录 warning，不阻塞下次执行（目录名 uuid 不冲突） |
| 容器残留 | 启动时 `cleanup_orphan_containers()` 批量清理 + 后台回收器定期扫描 |

## 9. 前端适配

`ArtifactPreview.tsx`：
- props 新增 `previewUrl?: string | null`
- iframe：`src={previewUrl ?? undefined}`，`srcDoc={previewUrl ? undefined : document_}`
- "在新标签页打开"：有 `previewUrl` 直接打开，否则用 Blob
- 状态文本：有 `previewUrl` 显示"沙箱隔离运行"，否则"本地预览 · 沙箱未启动"

`Index.tsx`：
- 新增 `previewUrl` state
- artifact 成功后从 `built.preview_url` 设置
- 切换项目 / 新建 / 恢复版本时清空

## 11. 运维与排障

```bash
# 查看运行中的沙箱容器
docker ps --filter name=atoms-sandbox-

# 查看所有沙箱容器（含已停止）
docker ps -a --filter name=atoms-sandbox-

# 手动清理所有残留沙箱容器
docker rm -f $(docker ps -aq --filter name=atoms-sandbox-)

# 查看工作区
ls $SANDBOX_ROOT  # 默认 /tmp/atoms_sandbox

# 拉取镜像（首次部署）
docker pull nginx:alpine
```

## 12. 不新增依赖

- 不引入 `docker` Python 包，用 `subprocess` 调 `docker` CLI。
- `nginx:alpine` 镜像需首次 `docker pull`，或在部署脚本中预拉取。
