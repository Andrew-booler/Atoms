# Atoms Studio 项目说明

> 面向自然语言 → 可运行网页原型的对话式工作台。保留本文档用于快速了解项目现状与下一步方向，完整路线图见 [roadmap.md](roadmap.md)。

## 一、实现思路与关键取舍

### 1. 总体架构

- 前端：React + Vite + SWC，内嵌 CodeMirror 6 编辑器。
- 后端：FastAPI + PostgreSQL，统一走「AI 编排 → 产物校验 → 版本落库 → Docker 沙箱预览」链路。
- 执行隔离：Docker `nginx:alpine` 只读挂载 + `--cap-drop=ALL` + `-p 127.0.0.1:<随机端口>:80`，产物是纯静态单文件 HTML，无需在沙箱内执行任意代码。

### 2. 核心链路

```
需求 → plan(计划) → outline(界面结构) → artifact(HTML) → sanitize → 存为版本 → 沙箱预览
                                        ↑ 迭代回路 / 代码编辑可回写为新版本
```

### 3. 关键取舍

| 决策点 | 选择 | 理由 |
|---|---|---|
| 编辑器 | CodeMirror 6 而非 Monaco | 轻量、可定制，够用且体积小 |
| 生成方式 | 三阶段编排而非一步出 HTML | 每阶段产物可独立校验/修复，出错定位清晰 |
| 语言支持 | 仅HTML | 项目初期仅支持 HTML，，无需复杂编译。后续可扩展其他语言 |
| 编辑保存语义 | 保存为新版本（保留历史）而非覆盖 | 可回溯，与版本体系一致 |
| 真实模型接入 | OpenAI 兼容的 `AsyncOpenAI`，模型集中配在 `MODEL_PROFILES` | 换模型只改一处；key 走环境变量不入代码 |
| 限流韧性 | 429/5xx/超时做指数退避+抖动重试 + 模块级信号量限并发 | 针对当前免费模型，后续可扩展至多模型混用或非免费模型。 |

## 三、后续扩展与优先级判断

**硬依赖链**（不可压缩）：`Phase 1 → Phase 4 （已完成）→ Phase 5 → Phase 6 → Phase 7/9`。横切 Phase 16/17 与主线无编号依赖，建议前置到 Phase 5 之前，落地顺序为 **16 → 17 → 5 → 6 → …**；Phase 16/17 均已完成，下一步主线为 Phase 5（详见 [roadmap](roadmap.md)「实现顺序与实施时点」）。

### 建议优先级

**P0 — 先补横切（安全、可读性与成本，现实风险）**
1. **Phase 16 统一业务异常体系（已完成 2026-11-04）**：错误统一为 `ErrorResponse{code, message, details?}`，`code` 用 `DOMAIN_REASON`，message 为中文可读句子
2. **Phase 17 登录/认证 + 多用户数据隔离（已完成 2026-11-04，仅本地验证）**
3. 服务端速率限制 + 请求体大小限制 + CORS 收紧
4. AI token 用量统计与成本配额

> 理由：真实 AI + 真实 key 已接入，上述缺口从"理论风险"变为"现实风险"，应在对外使用前补齐。

**P1 — 核心产品价值**
5. Phase 5 多 Agent 协作（角色体系 + 编排器，LangGraph 或自研轻量编排）
6. Phase 6 工具框架（可先做内置工具：覆盖率/Lint，MCP 与外部连接器后置）

**P2 — 可并行或后置**
7. Phase 8 生产预览通道**暂缓**（需域名 + DNS/反代等外部资源），Phase 9 发布部署**连带暂缓**；Phase 10 构建终端（仅依赖 Phase 1，可提前）；参见 [roadmap](roadmap.md) 的「实现顺序与实施时点」
8. Phase 7 安全扫描、Phase 9 发布部署**暂缓（连带 Phase 8）**、Phase 11 知识库、Phase 12 消息队列

**可提前/并行**：Phase 3 可与 Phase 2 并行；Phase 10 仅依赖 Phase 1、可提前；Phase 8 暂缓；Phase 12 依赖 Phase 5（或 Phase 4），不宜提前到 Phase 1/4 之前。
