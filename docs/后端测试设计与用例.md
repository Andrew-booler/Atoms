# 后端测试设计与用例

版本：1.2｜日期：2026-11-01｜状态：测试已建立并通过（23 项：17 单元 + 6 集成）｜配套：《测试策略与规范》《测试用例与覆盖矩阵》

## 阅读背景与必要概念

本文说明 Atoms Studio 后端应如何被单元测试和接口集成测试覆盖，执行结果见 §5。工作台让使用者提交需求、查看计划、确认构建、保存并预览 HTML 文档、恢复历史版本；后端负责保存项目、消息与版本，并把预置模拟输出返回给前端。

项目保存工作空间状态；消息保存需求、计划或系统备注；历史版本保存完整 HTML。id 是记录标识，version_no 是项目内版本序号，current_version 是项目当前使用的版本序号。单元测试只检查一个函数、类或职责对象，外部调用全部用替身（预置结果、调用记录或受控失败）；接口集成测试使用进程内的真实 HTTP 应用、真实业务路由和专用测试数据库，只有 AI 输出提供者仍返回预置结果。

HTTP 是前后端网络协议；GET 读取、POST 提交、DELETE 删除；200/201 成功，404 资源不存在或版本不属于项目，422 字段校验失败，500 提交失败，502 提供者明确失败。ASGI 是 Python 异步应用的调用接口，进程内调用不占用网络端口。schema 是 PostgreSQL 中隔离表的命名空间；本项目的测试宿主只允许以 `studio_test_` 开头的 schema。mock 是用预置结果或受控失败代替外部调用。

用例标题统一写作「文件::函数/方法 — 行为」，例如 `routers/studio.py::_plan_to_text — 展示用计划文本整理`；这样读者能直接确认每条用例针对哪个函数。函数不设单元用例时，必须在 §1.2 的函数覆盖清单中列明由哪一类证据覆盖。

## 2. 后端单元测试（12 条）

本节所有用例的共同前置条件：只导入被测模块或函数；数据库会话、HTTP 客户端、提供者和时钟全部用替身；不连接真实数据库，不发真实网络请求。共同界面结果：无页面变化，因为本层不运行浏览器。

### 后端-单元-01：`services/studio_output.py::get_provider` — 默认提供者与显式注入

- 被测对象：`get_provider()` 与模块级变量 `_provider`（第 61-66 行）。
- 前置条件：记录模块加载后的 `_provider` 原值，供用例结束后还原；准备一个只记录调用的替身提供者。
- 操作步骤：读取 `get_provider()`；把 `_provider` 设为替身；再次读取 `get_provider()`。
- 请求或外部替身调用：两次读取，不调用任何阶段方法。
- 预期响应：第一次返回 `MockOutputProvider` 实例；第二次返回注入的替身对象，且类型不是 `MockOutputProvider`。
- 持久化结果：无写入。
- 取出证据：两次返回对象的类型与 `id()`；结束后 `_provider` 已还原为原值，避免影响同进程内其他用例。
- 依据与状态：当前实现；已建立。

### 后端-单元-02：`services/studio_output.py::MockOutputProvider.plan/outline` — 两轮固定数据与深拷贝

- 被测对象：`MockOutputProvider.plan(requirement, **kwargs)`、`MockOutputProvider.outline(requirement, plan, **kwargs)`，以及其依赖的 `fixture(requirement)`（第 17-26、35-43 行）。

## 6. 术语补充

- 后端单元测试：只检查一个后端函数或职责对象，数据库、HTTP 与提供者全部替身，不连接真实服务。
- 接口集成测试：进程内调用真实 HTTP 应用与真实数据库，只模拟 AI 输出边界；不运行浏览器。
- 界面集成测试：Playwright 运行真实浏览器、真实前端、真实后端和测试数据库；只模拟 AI 输出边界。
- 受控提交失败：测试宿主在指定阶段让数据库提交抛出异常，用来验证回滚与错误映射，不代表真实故障率。
- 幂等：同一请求重复执行时不产生第二份业务结果。
- 函数覆盖清单：按「文件::函数/方法」列出对应用例或覆盖方式的表，用来核对没有函数被无声遗漏。
