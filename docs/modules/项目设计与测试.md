# 项目模块设计与测试

版本：3.1｜可读性修订日期：2026-10-31｜作者：Alex｜作者自检：已完成｜执行证据见《测试执行记录》

## 阅读背景与必要概念

本文供只初步了解工作台流程的读者阅读，不要求先阅读其他文档。Atoms Studio让使用者输入应用需求，先查看计划，点击“确认执行”后再取得界面结构和完整网页，保存到项目并预览。本阶段的目标是所有使用者共享同一账号和项目数据，操作逐项完成，AI输出由模拟提供者返回预先指定的数据（mock），不评价生成应用是否满足业务需求。当前业务路由共享读取数据、默认模拟输出；前端统一串行操作状态。验证结果与未覆盖子情景见测试执行记录。

- 项目是保存一组需求消息、计划消息和历史网页版本的容器；“当前打开的项目”指工作区正在显示的项目。
- 历史版本保存一份完整网页文本（HTML）。版本序号version_no表示同一项目的第几次成功保存；数据库记录标识id用于找到一条具体记录，两者不能互换。项目字段current_version表示项目当前使用的版本序号。
- 空闲表示上一项操作及其请求均已成功或失败结束；执行中表示这一项尚未结束。目标要求执行中不能开始另一项产品操作，不设置并发锁或队列。
- 前端是浏览器中的工作台；后端是处理请求并读写数据库的服务。HTTP接口是两者的通信约定：GET读取、POST提交、DELETE删除；200表示请求成功，201表示创建成功，404表示记录不存在或版本不属于所选项目，422表示请求字段无效，502表示输出提供者明确失败。数据库提交故障返回500，模拟结构无效返回502；错误反馈不伪造成功。
- 本文的“目标类”是后续职责设计，尚未创建。Controller是协调动作的控制器，Service是处理业务的服务，Repository是读写记录的仓储，UnitOfWork是统一提交或回滚一次数据库操作的工作单元。现有React仍使用函数组件，不能把这些目标名称当作已实现类。

## 1. 模块设计

### 1.1 适用范围

本文说明新建工作区、首次提交时创建项目、选择已有项目和删除项目。工作区是浏览器当前显示的消息、版本和预览；清空工作区不等于删除数据库项目。

### 1.2 现有对象与目标职责

现有Index事件处理、ProjectRail列表、studioApi接口封装及FastAPI路由承担项目流程。目标ProjectController管理工作区选择，ProjectService协调创建和删除，ProjectRepository、MessageRepository、VersionRepository分别读写对应记录，UnitOfWork统一提交删除操作。

### 1.3 正常操作及请求顺序

1. 使用者在空闲时点击“新建项目”。前端取消当前项目选择，清空消息、历史版本和预览，保留尚未提交的需求文字。这个按钮无网络请求，不创建也不删除数据库记录。

2. 使用者输入“记录饮水”并点击“生成计划”。若尚无当前项目，前端先发送POST /api/v1/studio/projects，字段name按需求文字合并空白后截取前24字符，超长加省略号，description为提交文字。返回201后才用新项目id保存需求消息、请求计划。

3. 使用者点击已有项目行，前端发送GET /api/v1/studio/projects/{project_id}，将占位符替换为所选项目数据库标识。返回200后展示project、messages、versions和current_artifact；读取不写数据库。

4. 使用者点击某项目行的删除按钮，前端发送DELETE /api/v1/studio/projects/{project_id}。后端成功提交该项目、关联消息和版本的删除后返回200及{deleted:true,id:项目标识}；前端移除该行，若删除的是当前打开项目则清空工作区。

### 1.4 失败、状态和未实施项

任一步失败结束后显示错误，不发下一阶段请求，也不显示伪造成功。当前选择成功读到详情后才切换活动项目，失败保留原工作区。项目最多60项，不新增分页或编辑名称页面。

篇幅估算：按A4 210×297毫米、20毫米边距、11pt、1.5倍行距、每页约40行；从“阅读背景与必要概念”标题起到篇幅说明前，按每个非空正文行每40字符向上取整并加一行间距，标题每个计三行；Markdown标记及技术标识计入字符数。设计含上述阅读背景，不含测试数据、测试用例及术语表，约76行、1.9页；这是估算，不是实际打印页数。估算少于三页，因此设计与测试同文件维护；实际排版达到三页时需要拆分。

## 2. 模块测试

### 本文使用的示例数据与测试条件

以下数字是测试设计中的示例，不是生产库的固定记录。示例项目数据库标识为101，名称为“演示项目”。它可以按用例分别准备为“尚无历史版本”或“已经保存两个历史版本”的状态，不能同时把这两种状态混作同一前置条件。另一个项目的标识为102；999表示该次测试中不存在的记录。

已经保存两个历史版本时：第1版记录标识为201，version_no=1，网页显示“模拟第一版”；第2版记录标识为202，version_no=2，网页显示“模拟第二版”。两条版本记录都属于项目101，项目最初当前使用第2版（current_version=2），历史版本总数为2。草稿状态则current_version=0、preview_ready=false，表示尚无可预览版本。preview_ready表示是否已有可预览网页。

第一轮需求文字为“记录饮水”。固定计划对象plan包含summary（摘要“演示计划一”）、stack（技术说明数组[“HTML”]）、steps（步骤数组，title为“显示演示”、detail为“使用预置页面”）、files（文件说明数组，path为“index.html”、purpose为“固定预览”）。第二轮需求是“增加备注”，第二轮计划摘要为“演示计划二”，完整预置数据在services/studio_output.py维护。

界面结构对象outline包含title（“演示页面一”）、sections（区域数组，每项有name和blocks）、interactions（交互说明数组）及seed_data（示例数据数组）。第二轮结构标题为“演示页面二”。完整HTML由services/studio_output.py中的fixed_html提供，第一版有初始值为0的“演示计数”按钮，仅用于验证装载和刷新；两版固定数据已创建，生产默认与隔离测试共用输出契约。

请求中的requirement是需求文字；content是消息正文；role是发言方（user为使用者，assistant为助手，system为系统），不是账号权限；kind是消息类别（requirement需求、plan计划、build构建、note备注）。meta是消息附加数据，接口以对象返回、数据库以JSON文本保存。profile是提供者配置键，沿用balanced、fast、quality；本阶段目标均返回模拟输出，不调用真实模型。

plan_summary虽然名为“计划摘要”，当前前端实际发送planToText整理的文本：计划摘要、空行，以及每个步骤的编号、标题和说明。上述第一轮示例的值为“演示计划一\n\n1. 显示演示 — 使用预置页面”（\n表示换行），不是只有“演示计划一”。后文称“该轮整理后的计划文本”时均使用此规则。artifact_html是返回或保存的完整网页文本；项目详情中的current_artifact是项目当前使用版本的网页文本。

单元测试只加载一个页面或职责对象，网络、SDK（前端接口调用封装）、数据库、输出提供者、剪贴板、窗口及定时器等外部调用全部使用模拟替身，不实际请求或写库。集成测试组合实际页面、SDK、业务后端和专用测试数据库，只有AI提供者返回固定模拟结果；共享业务路由、模拟提供者及隔离数据库已建立；逐项执行证据见测试执行记录，不将设计的全部子条件视为已验证。每例独立准备数据，按顺序操作。

### 单元测试

#### 项目-单元-01：新建工作区

- 前置条件：已有打开项目及尚未提交的文字；外部依赖全部模拟。
- 操作步骤：点击新建项目。
- 请求或外部替身调用：无网络请求；创建项目接口替身不能被调用。
- 预期响应：没有创建响应。
- 界面结果：取消当前项目选择，清空消息、历史版本和预览，保留尚未提交的输入文字。
- 持久化结果：原项目不删除，不新增记录。
- 依据与状态：当前代码；未执行。

#### 项目-单元-02：列表与选择

- 前置条件：单元隔离，分别模拟加载中、0项、1项、60项及详情成功或失败。
- 操作步骤：查看列表并依次选各项目。
- 请求或外部替身调用：列表和详情接口使用替身，记录每次所选项目标识。
- 预期响应：各组返回指定列表、详情或受控错误。
- 界面结果：显示加载提示、空列表或名称；成功显示对应项目，失败显示错误，不构造成功详情。
- 持久化结果：不请求真实数据库。
- 依据与状态：当前实现与设计；执行结果及子情景差异见测试执行记录。

#### 项目-单元-03：删除项目

- 前置条件：分别准备当前项目和非当前项目，接口全部模拟。
- 操作步骤：点击目标行删除；分别模拟成功和失败，再尝试执行中重复动作。
- 请求或外部替身调用：删除替身记录目标项目标识；目标执行中不发生新调用。
- 预期响应：成功或受控失败按组返回。
- 界面结果：成功移除目标；当前项目删除清工作区；失败保留行并提示。
- 持久化结果：无真实写库。
- 依据与状态：当前删除流程与统一串行状态；未执行。

### 集成测试

#### 项目-集成-01：新建到首次提交

- 前置条件：项目101已有两个历史版本，页面空闲。
- 操作步骤：打开项目101，输入记录饮水，点击新建项目，再点击生成计划。
- 请求或外部替身调用：新建无网络请求；提交先POST /api/v1/studio/projects，{name:"记录饮水",description:"记录饮水"}；取得新id后，POST /api/v1/studio/projects/{project_id}/messages，{role:"user",kind:"requirement",content:"记录饮水"}；再POST /api/v1/studio/projects/{project_id}/plan，{requirement:"记录饮水",profile:"balanced"}。两个路径的project_id均替换为新返回标识。
- 预期响应：分别返回201项目摘要、201需求消息、200及plan/message/model。
- 界面结果：新工作区显示新项目、需求和固定计划，没有网页预览。
- 持久化结果：新增一个项目、一条需求消息、一条计划消息，没有历史版本；旧项目101内容不变。
- 依据与状态：当前实现与设计；执行结果及子情景差异见测试执行记录。

#### 项目-集成-02：选择共享项目

- 前置条件：独立准备无版本项目101，以及另一个已保存两个版本的项目102；后者当前使用第2版，具体版本记录标识由该次准备返回，不复用201/202。
- 操作步骤：先选101，读取结束后再选102。
- 请求或外部替身调用：依次GET /api/v1/studio/projects/101、GET /api/v1/studio/projects/102。
- 预期响应：每次200，返回project/messages/versions/current_artifact。
- 界面结果：101显示空预览，102显示自身消息和第2版网页，不把101的示例版本错误关联给102。
- 持久化结果：只读，共享目标不按使用者分割项目。
- 依据与状态：当前实现与设计；执行结果及子情景差异见测试执行记录。

#### 项目-集成-03：删除当前与非当前项目

- 前置条件：项目101和102均存在，打开101。
- 操作步骤：先删除102，结束后删除101，分别复查。
- 请求或外部替身调用：DELETE /api/v1/studio/projects/102，成功后GET /api/v1/studio/projects/102；另次DELETE /api/v1/studio/projects/101，成功后GET /api/v1/studio/projects/101。
- 预期响应：删除返回200及deleted/id；被删详情读取返回404。
- 界面结果：删102不清101预览；删101清工作区。
- 持久化结果：仅删除目标及所属消息、版本；没有新增撤销或删除确认功能。
- 依据与状态：当前删除契约；未执行。

#### 项目-集成-04：创建或删除失败

- 前置条件：每组独立准备专用数据，上一操作已结束。
- 操作步骤：分别提交无效创建字段、注入提交故障、删除不存在项目999或注入删除故障。
- 请求或外部替身调用：POST /api/v1/studio/projects，name缺失或空串；DELETE /api/v1/studio/projects/999；提交故障组使用合法name及目标项目路径。
- 预期响应：无效字段422，不存在项目404；数据库提交故障不得返回成功，返回500。
- 界面结果：创建失败不继续保存需求或请求计划；删除失败不移除目标，错误可见，结束后可再操作。
- 持久化结果：失败操作不能被记录为成功创建或删除。
- 依据与状态：当前实现与设计；执行结果及子情景差异见测试执行记录。

#### 项目-集成-05：列表容量与刷新

- 前置条件：分别准备0、1、60、61个项目；每组独立。
- 操作步骤：打开工作台，结束后手选一个可见项目；刷新再手选。
- 请求或外部替身调用：前端依次发送GET /api/v1/studio/projects和GET /api/v1/studio/models；任一读取结束后才开始另一读取，产品不额外规定两者谁先。选择时GET /api/v1/studio/projects/{project_id}，使用所选标识。
- 预期响应：两个请求分别返回200：项目摘要列表，以及profiles配置列表与default_profile默认配置。详情读取200。
- 界面结果：现有列表最多60项，按更新时间和id倒序；第61项可能无入口，刷新不自动选择。
- 持久化结果：读取保存记录，不承诺未提交草稿恢复；维持最近60项目与最早400消息，不新增分页。
- 依据与状态：当前实现与设计；执行结果及子情景差异见测试执行记录。

## 3. 术语补充

- 版本记录标识：数据库id，用于定位记录；版本序号version_no仅表示项目内第几版。
- 项目当前使用的版本序号：current_version字段；恢复修改这个值，不改写历史HTML。
- 持久化：把记录提交到数据库，之后可通过实际读取接口核对，不等于仅在页面显示。
- 事务：一组数据库写入一起提交或回滚；多次HTTP请求不自动组成一个事务。
- SDK：前端业务调用封装，本项目通过它向后端发送请求。
- 目标设计：未来获批实施的职责或规则，不能据此认定当前代码已实现。

## 3. 当前实施与执行对应

本轮用户已授权实施，不设强制外部审阅。默认输出在services/studio_output.py；Index和StudioOperation串行协调SDK请求，成功/失败均释放状态。批准写计划meta；调整取所点计划需求；重试重发失败阶段；恢复摘要立即同步，部分成功明确提示并仅读取重试。项目60条、消息最早400条容量保持原状。手机新增项目抽屉打开与关闭两类控件。

上文七项式用例保留设计追溯，其中历史“未执行”只表示原文档阶段；本轮实际运行脚本与子情景差异以[测试执行记录](../测试执行记录.md)为准。自动化同编号的标题和断言并不覆盖原设计每个子条件，不能仅由标题数量推导全部设计通过。
