# 测试策略与规范

版本：3.1｜修订日期：2026-10-31｜配套：《测试用例与覆盖矩阵》

> 本轮已授权实施并建立两层测试。设计覆盖不等于执行通过；具体命令和结果见[测试执行记录](测试执行记录.md)。

## 阅读背景与必要概念

本文说明 Atoms Studio 应如何设计和报告测试，不是本轮已执行的结果。工作台让使用者提交需求、查看计划、确认构建、预览保存的 HTML 文档并恢复历史版本。HTML 是浏览器显示页面的文字格式。目标是共享账号和数据、操作串行及 AI 输出模拟；当前Studio路由共享读取、默认模拟输出，前端统一串行状态。

项目保存工作空间状态；消息保存需求、计划和备注；历史版本保存完整 HTML。id 是记录标识，version_no 是项目内序号，current_version 保存项目当前使用的版本序号。单元测试检查一个类或页面，所有外部调用均用 mock（预置结果、调用记录或受控失败替身）替代；集成测试使用真实页面、业务接口及专用测试数据库，仅 AI 输出模拟，不增加第三层，也不评估生成质量。

HTTP 是前后端网络协议，API 是接口约定，SDK 是前端请求封装。GET 读取、POST 提交、DELETE 删除；200/201 成功，404 资源不存在或版本不属于项目，422 字段校验失败，502 提供者明确失败。路径中的 {project_id} 由项目记录 id 替换。requirement 是本轮需求，plan_summary 是整理后的计划文本而非只有摘要，outline 是页面结构，artifact_html 是完整 HTML；profile 是提供者配置键，balanced 是现有默认值。计划对象 Plan 包含摘要、技术说明、步骤和文件说明；结构对象 Outline 包含标题、区域、交互和初始数据。事务只保证其中的数据库写入一起成功或撤销。

iframe 是嵌入预览容器，srcDoc 是传入 HTML 的属性，sandbox 是浏览器限制配置，Blob 是外开预览的临时内容。计划卡是展示计划及确认、调整、复制的区域；示例提示按钮只把示例文字填入输入框。设计映射只表明需求与用例已经关联，不表示执行覆盖率。


## 1. 本阶段范围与证据

### 1.1 新需求

所有使用者共享同一账号和项目数据上下文。登录认证、用户管理、角色、权限、租户隔离不属于本阶段需求或测试范围。产品认证路由和登录入口已移除；平台受保护认证实现保留但不挂载为产品功能。

所有操作串行：前一项成功或失败结束后，才允许下一项开始。同一个动作里的请求依次等待，不设计多用户并发、多标签同时操作、并发锁、任务队列或并发压力测试。执行中的操作不能由另一个产品按钮打断；浏览器强制关闭和刷新不属于可禁用产品按钮。

AI输出使用mock，即预置模拟计划、界面结构和HTML。保留未来真实AI提供者的可替换服务入口，不调用真实模型，也不测试生成工程质量、语义质量、输出是否满足需求、提示词效果或模型稳定性。只测试固定响应怎样在产品中传递、展示、保存、读取和预览。

### 1.2 证据和范围分母

证据来自实际代码：`app/frontend/src/App.tsx`、Index/DeployPage/CloudPage、ProjectRail/PlanCard/ArtifactPreview/RequirementComposer/ConversationStream/PlaceholderPanel、`lib/studio.ts`、`app/backend/routers/studio.py`和`services/studio_output.py`，以及项目与版本模型、依赖清单。需求与架构依据本轮用户确认，不把代码现状视作已经符合新需求。

新版范围：3个业务页面、26类固定交互目标（原24类加手机抽屉打开/关闭按钮）、7个模块、14个用户场景、56条用例（21条单元测试、35条集成测试）。重复项目行、四个示例提示按钮、不同计划状态必须参数展开。计数和映射见配套矩阵。

原登录/退出/去登录/关闭登录提示/认证返回5类交互及两个认证页面从范围移除。未挂载页面、模板通用实体接口、其他模板管理和存储接口不是本阶段产品模块，不将其数量加进覆盖分母。工作台使用的11个Studio接口均有业务集成映射。

## 2. 测试只有两个层面

### 2.1 单元测试

对象为一个类或页面；现有函数组合模块按其职责作为对象，不为测试强行改写业务代码。页面对象可以是工作台、计划展示区域、预览区域或占位页面。

该对象所有外部调用均mock：网络和SDK、数据库、文件或对象存储、AI提供者、剪贴板、外开窗口、浏览器地址对象、定时器及其他外部依赖。只观察对象的输入输出、显示状态和对mock的调用记录，不访问实际业务服务。模拟子页面/协作对象，不将多个实际业务对象组合冒充单元测试。

例：给计划展示页面一个固定计划，点击复制；剪贴板调用使用mock，检查写入文本和“已复制”显示，不使用真实系统剪贴板。数据库调用对象也只能操作mock会话，不写数据库。

### 2.2 集成测试

组合真实页面、SDK业务请求、真实Studio路由、数据处理和专用测试数据库；**只有AI输出提供者仍使用预置模拟响应**。不得把整个HTTP接口返回值mock后称作持久化集成验证。

逐例写明前置条件、用户动作、HTTP方法与路径、必要字段、预置提供者结果、预计响应、可观察页面变化和数据结果。纯界面动作明确写“无网络请求”。实际保存通过响应后再次读取业务接口核对，数据库提交故障可由测试环境受控注入，不访问共享生产数据。

页面互操作、请求校验、数据库提交和预览检查均属于集成测试，不另设端到端、接口、组件或安全测试层级。必要的键盘、窄屏、固定HTML宿主行为也归入这两个层面。

## 3. 框架选型与统一原则

**主要运行框架确定为 Playwright Test（包名 @playwright/test）**。项目依赖清单已有该包；它同时具备断言、mock记录、浏览器页面、请求发送和结果追踪能力，可统一页面单元与模块集成的运行入口，避免再引入Vitest、MSW、axe等独立工具链。

| 工具 | 用途 | 不增加层级的约束 |
|---|---|---|
| Playwright Test | 运行前端类/页面单元、业务集成；记录步骤、请求和响应 | 单元使用隔离对象及外部mock；集成访问实际业务服务，AI边界模拟 |
| Playwright浏览器与请求能力 | 页面点击、键盘、iframe检查、向实际服务发送请求和复查保存结果 | 属于Playwright Test自身能力，不是第三个测试层级 |
| pytest + pytest-asyncio | 必要辅助执行器，仅运行Python服务/路由对象单元测试 | Python对象不能直接由JavaScript框架调用；所有外部依赖仍mock，统一归入单元测试 |
| unittest.mock | Python网络、数据库及提供者调用替身 | Python标准库，不安装额外mock框架 |

当前页面单元采用React服务端静态渲染及替身回调，对StudioOperation使用受控Promise验证；不执行浏览器挂载点击。真实点击交互归入集成，静态单元不能宣称完整点击行为验证。Playwright Test不能直接执行Python对象，也不能把HTTP测试当作Python单元测试，因此保留现有pytest作为必要辅助，而不是宣称一套运行器可跨语言直接执行所有对象。

前端mock使用统一预置结果及调用记录适配，不额外引入网络拦截框架。Python集成不另建HTTPX/数据库测试运行链，使用Playwright请求能力访问部署在专用环境中的实际后端。复用现有依赖；测试配置独立运行服务，浏览器安装只服务测试，不改变产品依赖。

## 4. 模拟数据与接口契约

### 4.1 固定数据

- “第一轮计划”：summary为“演示计划一”；stack为固定数组；steps含title/detail；files含path/purpose。
- “第一轮结构”：title为“演示页面一”；sections含name/blocks；interactions和seed_data为固定字符串数组。
- “第一版HTML”：完整HTML，显示“模拟第一版”和固定“演示计数”按钮，计数从0开始。该按钮仅证明正确文档已装入预览，不评估需求满足程度。
- 第二轮使用另一套固定计划、结构和显示“模拟第二版”的HTML。两版完整文本不同，可精确核对保存及读取的字符串。
- 失败数据：提供者明确失败、延迟后成功、缺必要字段、空HTML；业务对象不存在、必要字段无效、受控提交失败。
- 输入数据：空白、中文多行、emoji、1999/2000/2001字及10000字；项目数量0/1/60/61；消息399/400/401。不是随机生成质量样本。

模拟数据仅在提供者或单元外部依赖边界设置；不在业务请求里擅加mock选择字段。默认MockOutputProvider按需求含“增加备注”选择第二套固定响应，否则第一套；没有新增业务开关。隔离测试宿主注入受控提供者。

### 4.2 三阶段接口

路径前缀 `/api/v1/studio`：

| 接口 | 请求 | 模拟提供者成功后响应 | 失败及下游行为 |
|---|---|---|---|
| POST /api/v1/studio/projects/{project_id}/plan | requirement、profile | 200：plan、message、model；计划消息保存 | 提供者失败502及detail；不展示成功计划、不自动调用下一阶段 |
| POST /api/v1/studio/projects/{project_id}/outline | requirement、plan_summary、profile | 200：outline、model；此阶段不保存版本 | 失败502及detail；不发起后续 HTML 构建请求 |
| POST /api/v1/studio/projects/{project_id}/artifact | requirement、plan_summary、outline、profile | 200：project、version、message、outline_title、artifact_html；一次保存完整版本 | 失败502及detail；不保存成功版本或构建消息 |

输入缺必要字段返回422，资源不存在或版本不属于项目返回404。数据库提交失败不得返回成功，不得留下只保存版本却没有项目当前使用的版本序号的部分结果；提交异常回滚返回500，模拟结构校验失败返回502。全部11个Studio接口的字段及响应由[总架构](总架构设计.md)定义，[矩阵](测试用例与覆盖矩阵.md)逐项追溯。

未来真实AI接入保持上述三阶段输入输出和失败契约，替换提供者即可；本阶段不测试真实AI调用，也不约定模型质量阈值。

### 4.3 第二轮内容传递的可读说明

第一轮输入“记录饮水”，确认后保存第一版模拟HTML。第一轮操作全部结束后，在同一项目输入第二轮文字“增加备注”：
1. 使用者在项目 101 空闲时提交“增加备注”。系统发送 `POST /api/v1/studio/projects/101/messages`，请求 role="user"、kind="requirement"、content="增加备注"；响应 201 返回保存的需求消息。随后发送 `POST /api/v1/studio/projects/101/plan`，请求 requirement="增加备注" 及 profile；响应 200 返回第二轮固定 plan、保存的 message 和 model，界面显示待确认计划。
2. 使用者确认后，系统把第二轮摘要与编号步骤整理为 plan_summary；第一轮对应示例是 `演示计划一\n\n1. 显示演示 — 使用预置页面`，第二轮必须使用第二轮固定计划的文本，而非沿用第一轮摘要。系统发送 `POST /api/v1/studio/projects/101/outline`，请求第二轮 requirement、plan_summary、profile；响应 200 返回第二轮 outline 和 model，不保存版本。
3. 系统等待结构成功，再发送 `POST /api/v1/studio/projects/101/artifact`，请求同一轮 requirement、plan_summary、outline、profile；响应 200 返回 project、version、message、outline_title、artifact_html。后端在一次事务中保存第二版、构建消息并更新 current_version。
4. 界面显示第二版 HTML；测试发送 `GET /api/v1/studio/projects/101` 核对 project.current_version=2、versions 中有两版、current_artifact 为第二版，并读取第一版历史详情确认原文不变。项目 101 是测试准备取得的示例 id；实际执行用准备返回的 id 替换。

当前请求不携带第一轮对话列表，也不携带第一版HTML。**这描述的是发送字段，不是判断AI是否理解上下文。** 本阶段只检查第二轮字段归属、顺序和固定响应保存，不要求保持前版应用功能。未来是否加历史内容字段待确认，不能成为本阶段测试失败判据。

## 5. 串行操作规范

一项操作包括其子请求；例如首次提交包含建项目、存消息、取计划，确认执行包含取结构、取产物并保存。全部子请求成功或任何一步失败结束后才回到空闲。

执行中禁止下一项操作：主导航、新建、项目选择、删除、示例提示、提交与快捷键、确认/调整/复制、配置选择、预览宽度/刷新/外开和版本选择均不能触发新动作。输入编辑也按新串行目标暂停；结束后恢复。集成测试逐个尝试这些控件，断言无新增请求和无页面切换，而不是设计多个操作同时成功的并发场景。

初始化列表和配置也依次读取，先后顺序不额外指定。模拟延迟仅用来观察“执行中”状态；不同时发两个业务请求，不验证锁竞争或并发版本号。

当前StudioOperation统一busy状态，初始化先项目列表后配置，输入/导航/预览/版本在busy时禁用；延迟测试结果单独记录。

## 6. 当前实施规则与限制

共享路由不按user_id过滤，新写入使用studio-shared非凭据标识；不暴露服务端凭据。默认MockOutputProvider保留Plan/Outline/HTML契约；真实提供者仅显式适配接口，不被产品创建。操作与子请求串行，finally恢复状态。需求完整保存，计划批准与版本同事务写入；重试闭包保留成功阶段并执行失败动作。恢复立即同步摘要，读取失败清空旧预览并如实提示。

项目最近60、消息最早400保持原状，不新增分页；超过容量的响应丢失核对不承诺完全去重。未提交草稿刷新不恢复。手机最小项目抽屉已接入。部署与Cloud只占位。

取消、流式、跨标签协调、真实AI质量和生成工程任意内部按钮不在范围。

## 7. 用例、执行和报告规范

用例按导航、项目、需求输入、计划、模拟构建、预览、版本七个模块分类，详细设计和测试统一位于[模块索引](README.md)，每模块单独列“单元测试”和“集成测试”。编号使用“模块名称-单元-序号”或“模块名称-集成-序号”，不使用单一字母表示概念。

每例必须写：完整标题、前置条件、动作、mock或请求数据、预计响应、界面和数据结果、依据。依据使用“新目标”“当前代码”“待确认”完整名称。设计状态和实际脚本结果分开；未覆盖子情景标未执行，不按同编号自动推定通过。

纯界面操作写“无网络请求”；单元写“外部调用全部mock”。集成记录实际发起的请求与复查结果，不以页面文字单独证明保存成功。报告区分设计映射、已执行、通过、失败、阻塞和待确认；执行为0时通过率不适用。

缺陷等级使用完整中文：致命（核心数据损坏或主流程不可用）、严重（请求与界面结果不一致、操作不能按顺序执行）、一般（局部反馈或可读性问题）、轻微（非关键文案排版）。等级不代表已发生缺陷，不设置未经确认的百分比发布阈值。

执行准入：文档规范确认、共享上下文及模拟提供者已实施、独立测试数据环境就绪、框架和隔离单元入口获准建立。当前已建立测试宿主、默认mock和独立数据库命名空间；启动失败等环境证据同样记录，不冒充产品通过。

后续迭代顺序：更新模块需求及控件清单 → 修订相关单元与集成用例 → 单元测试 → 集成测试 → 记录缺陷及结果。新增按钮增加映射；模拟数据改动同步预期，不引入真实生成评分。

## 8. 术语表

- 单元测试：仅检查一个类或页面，所有外部调用使用mock。
- 集成测试：检查模块之间真实交互、业务请求和持久化，AI提供者仍返回预置模拟输出。
- mock：用预置结果、调用记录或受控失败代替外部调用。
- 示例提示按钮（旧称示例芯片）：点击后将一条示例需求填入输入框，不自动提交；四个按钮均须检查。
- 计划卡：显示计划摘要、步骤和文件说明的区域，包含确认执行、调整需求和复制计划按钮。
- 抽屉：从页面边缘展开并可收起的面板；手机已提供项目抽屉。
- Playwright Test：本项目主要测试运行框架，可操作浏览器、发送请求并断言结果。
- pytest / pytest-asyncio：Python单元的必要辅助运行工具及异步支持，不构成额外测试层级。
- SDK：页面调用业务接口的封装库。
- HTTP方法与状态码：GET用于读取，POST用于提交，DELETE用于删除；200/201成功，404资源不存在，422请求字段无效，502提供者失败。
- profile：接口中的提供者配置键，当前使用模拟输出而非真实模型。
- JSON：组织接口对象和数组的数据格式。
- HTML：预置预览文档格式，artifact_html字段保存其完整文字。
- iframe / srcDoc / sandbox：嵌入预览容器、直接传入HTML的属性及其浏览器限制配置。
- Blob：浏览器临时内容对象，用于外开预览，不是部署链接。
- 快照：一版完整HTML记录；项目当前使用的版本序号指示当前展示哪一版。
- 串行操作：前一操作成功或失败结束后再执行下一操作。
- 持久化：将项目、消息和版本保存到数据库，刷新后可再次读取。

## 9. 实际运行入口与隔离
