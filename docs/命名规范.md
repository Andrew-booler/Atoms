# 命名规范

版本：1.0｜日期：2026-11-04｜状态：现行规范，适用于后续维护与审阅

## 阅读背景与必要概念

本文说明 Atoms Studio 代码、数据、接口、错误码与文档中名称如何书写与组织。工作台接受文字需求，展示计划，确认后生成页面结构并保存 HTML 文档，随后在隔离预览中打开，也可恢复历史版本。

本文只规定命名，不规定业务规则、分层职责或测试方法。分层与职责见[开发规范](开发规范.md)，目录与模块划分见[总架构设计](总架构设计.md)，测试分层见[测试策略与规范](测试策略与规范.md)。本文由原《开发规范》§3 与《总架构设计》§4 中的命名内容迁入并集中维护；原处只保留摘要与指向本文的链接，不再保存第二份详细规则。

必要概念：PascalCase 表示每个单词首字母大写，如 `ProjectService`；camelCase 表示首个单词小写、后续单词首字母大写，如 `currentVersion`；snake_case 表示小写单词用下划线连接，如 `current_version`；UPPER_SNAKE_CASE 表示大写单词用下划线连接，如 `MAX_LENGTH`；kebab-case 表示小写单词用中划线连接，如 `execution-sandbox`。错误码是由业务域与失败原因两段组成的全大写标识，见第 6 节。

## 1. 通用规则

1. 名称必须能读出业务含义，使用 `Project`、`Version`、`Requirement`、`Artifact` 等完整词；禁止用 `a`、`x`、`tmp`、`data1` 等单字母或无信息缩写表达业务概念。
2. 同一概念在代码、文档、接口与错误文案中使用同一名称；项目与历史版本分别叫 `Project` 与 `StudioVersion`，不使用 `proj`、`ver` 等变体。
3. 已被外部依赖的名称（数据库表字段、HTTP 路径、环境变量、已有错误字段）保持兼容，不因本规范重命名；新增名称按本文执行。
4. 中文只用于文档正文与用户可见文案；标识符、文件名、接口字段、日志键一律使用英文。
5. 不使用拼音作为标识符（如 `xiangmu`、`banben`）。

## 2. 前端（TypeScript / React）

| 对象 | 规则 | 示例 |
|---|---|---|
| 类、接口、类型别名 | PascalCase | `StudioOperation`、`ProjectSummary`、`BuildResponse` |
| 函数、变量、对象属性 | camelCase | `currentVersion`、`previewUrl`、`restoreVersion()` |
| React 页面与组件 | PascalCase，文件同名 `.tsx` | `pages/Index.tsx`、`ArtifactPreview.tsx` |
| 自定义 Hook | `use` 前缀 + PascalCase | `useStudioSession` |
| 常量（模块级不可变配置） | UPPER_SNAKE_CASE | `MAX_REQUIREMENT_LENGTH` |
| 事件处理函数 | `handle` + 动作 PascalCase，或 `on` 前缀的属性 | `handleSubmit`、`onConfirm` |
| 目录 | 小写；需要分隔时用 kebab-case | `components/studio`、`lib`、`components/ui` |
| 单元测试文件 | 与被测对象同名 + `.test.ts` / `.test.tsx` | `studio.unit.test.tsx` |
| 界面集成测试文件 | `.spec.ts` | `studio.integration.spec.ts` |
| 样式 | 只有全局 `index.css`；组件样式用 Tailwind utility class | — |

React 组件一律使用函数组件与 PascalCase；禁止为命名整齐而强行改成类组件。测试文件不得放进 `src/`。

## 3. 后端（Python / FastAPI）

| 对象 | 规则 | 示例 |
|---|---|---|
| 类（含 Pydantic 模型、ORM 实体、异常） | PascalCase | `StudioVersion`、`ArtifactRequest`、`AppError` |
| 模块、函数、方法、变量 | snake_case | `studio_validation.py`、`validate_artifact_html()`、`version_id` |
| 常量与环境变量 | UPPER_SNAKE_CASE | `SHARED_CONTEXT`、`SANDBOX_IDLE_TIMEOUT` |
| 私有辅助函数 | 前导单下划线 + snake_case | `_load_project()`、`_try_run_preview()` |
| 包与目录 | 小写 snake_case | `routers/`、`services/`、`schemas/`、`testing/` |
| 单元测试文件 | `test_` 前缀 + 被测模块 snake_case | `test_studio_validation.py` |
| 接口集成测试文件 | `test_` 前缀 + 作用域 | `test_studio_api.py`、`test_auth_api.py` |
| 测试数据库 schema | 必须以 `studio_test_` 开头 | `studio_test_api`、`studio_test_t1` |

Pydantic 传输对象按用途命名：请求用 `XxxRequest`，响应用 `XxxResponse`；避免用 `XxxModel` 混淆传输对象与 ORM 实体。异常类见[开发规范](开发规范.md)错误处理章节与 roadmap Phase 16。

## 4. 数据库与 HTTP 接口

- SQL 表与字段沿用现有 `projects`、`studio_messages`、`studio_versions`、`executions` 及 snake_case 字段；新增字段同样使用 snake_case，如 `user_id`、`expires_at`。
- 自动生成的 ORM 类名 `Projects`、`Studio_messages`、`Studio_versions` 是框架产物与代码事实，不因命名规范重命名；目标领域对象统一写 `Project`、`StudioMessage`、`StudioVersion`，并在文档中说明映射关系。
- HTTP 路径沿用既有复数资源与动作路径，如 `/api/v1/studio/projects/{project_id}/artifact`；新增路径使用小写 kebab-case 或复数资源，不制造同一动作的别名接口。
- 路径参数与查询参数使用 snake_case，与后端字段一致；不要在 JSON 中混用 camelCase 与 snake_case 表达同一概念。

## 5. 文档与用例编号

- 用例编号固定为「模块-单元-序号」与「模块-集成-序号」，如 `计划-单元-01`、`构建-集成-05`；新增作用域沿用同一形式，如 `后端-单元-01`。
- 正式文档使用清晰中文标题与模块名称；文件名使用中文或既有英文名，不新增拼音文件名。
- Phase 编号只追加、不重排；编号与实施时点解耦，见 [roadmap](roadmap.md)「实现顺序与实施时点」。

## 6. 错误码命名规范（DOMAIN_REASON）

Phase 16 统一业务异常体系对外返回 `ErrorResponse{code, message, details?}`（已于 2026-11-04 落地）。错误码是稳定契约，前端按 `code` 决定展示文案，因此命名必须在实施前一次定好。

### 6.1 组成规则

- 形式固定为 `DOMAIN_REASON`：两段、全大写、下划线连接、不使用中划线或驼峰。
- `DOMAIN` 表示业务域，取固定枚举，不允许自由创造：

| DOMAIN | 覆盖范围 | 示例 |
|---|---|---|
| `STUDIO` | Studio 三阶段编排、项目/消息/版本业务 | `STUDIO_PLAN_INVALID`、`STUDIO_ARTIFACT_INVALID` |
| `SANDBOX` | 执行与隔离层（Docker、镜像、端口、容器） | `SANDBOX_DOCKER_UNAVAILABLE`、`SANDBOX_IMAGE_PULL_FAILED` |
| `ARTIFACT` | 产物体积与内容约束 | `ARTIFACT_TOO_LARGE` |
| `AUTH` | 登录、会话、凭据、越权 | `AUTH_INVALID_CREDENTIALS`、`AUTH_REQUIRED`、`AUTH_FORBIDDEN` |
| `RATE` | 限流与配额 | `RATE_LIMITED` |
| `DB` | 数据库提交、迁移、连接 | `DB_COMMIT_FAILED` |
| `INTERNAL` | 未分类兜底 | `INTERNAL_ERROR` |

- `REASON` 描述具体失败原因，使用「名词/形容词 + 过去分词或状态」的短词组：`BUILD_FAILED`、`PLAN_INVALID`、`OUTLINE_INVALID`、`COMMIT_FAILED`、`TOO_LARGE`、`TIMEOUT`。禁止写成句子、中文、HTTP 状态码或异常类名。

### 6.2 硬性约束

1. **一码一义**：同一 code 只对应一种失败原因与一个 HTTP 状态；不同原因不得复用同一 code。
2. **不复用 HTTP 语义**：不得使用 `ERROR_500`、`NOT_FOUND`、`BAD_REQUEST` 这类与状态码同义的 code；code 表达业务原因，状态码单独由异常类型决定。
3. **禁止暴露实现细节**：code 与 message 不得包含堆栈、SQL、文件绝对路径、供应商原始报错文本。
4. **message 与 code 分离**：code 稳定、供程序判断；message 是可改写的用户可读中文句子，两者不互相替代。
5. **新增前查重**：在 `core/error_codes.py` 常量表中检索，确认无同义码；新码必须同时登记本文第 6.1 节所属域与 roadmap Phase 16 的码表。
6. **兜底唯一**：未知异常统一映射为 `INTERNAL_ERROR`，不得为每种未知异常临时造码。
7. **命名与异常类分开**：异常类名用 PascalCase（`SandboxUnavailableError`），code 用 `DOMAIN_REASON`（`SANDBOX_DOCKER_UNAVAILABLE`），不要求二者字面相同。

### 6.3 示例映射

| code | 含义 | HTTP 状态 | 用户可见 message（示例） |
|---|---|---|---|
| `STUDIO_PLAN_INVALID` | 计划结构不符合约定 | 502 | 计划内容不完整，请重新生成计划。 |
| `STUDIO_OUTLINE_INVALID` | 页面结构不符合约定 | 502 | 页面结构生成失败，请重试。 |
| `STUDIO_ARTIFACT_INVALID` | HTML 文档不完整 | 502 | 页面生成结果不完整，请重试。 |
| `STUDIO_DB_COMMIT_FAILED` | 业务写入提交失败 | 500 | 保存失败，请稍后重试。 |
| `SANDBOX_DOCKER_UNAVAILABLE` | Docker 未安装或未启动 | 503 | 预览服务暂不可用，已保存内容仍可查看源码。 |
| `SANDBOX_IMAGE_PULL_FAILED` | 沙箱镜像拉取失败 | 503 | 预览环境初始化失败，请稍后重试。 |
| `ARTIFACT_TOO_LARGE` | 产物超过体积上限 | 413 | 页面内容过大，请精简后重试。 |
| `RATE_LIMITED` | 触发服务端限流 | 429 | 操作过于频繁，请稍后再试。 |
| `AUTH_REQUIRED` | 未登录或会话失效 | 401 | 请先登录后再继续。 |
| `AUTH_INVALID_CREDENTIALS` | 用户名或密码错误 | 401 | 账号或密码不正确。 |
| `AUTH_FORBIDDEN` | 无权访问该资源 | 403 | 你无权访问该内容。 |
| `INTERNAL_ERROR` | 未分类异常 | 500 | 服务暂时不可用，请稍后重试。 |

以上 code 已于 Phase 16 落地；实际注册码表（31 个）以 `app/backend/core/error_codes.py` 为准，message 文案可微调，但必须保持「用户可直接读懂的中文句子」。

Phase 16 新增并已注册的 code（按域）：

- `STUDIO`：`STUDIO_PLAN_FAILED`（502）、`STUDIO_OUTLINE_FAILED`（502）、`STUDIO_ARTIFACT_FAILED`（502）、`STUDIO_PROJECT_NOT_FOUND`（404）、`STUDIO_VERSION_NOT_FOUND`（404）、`STUDIO_EXECUTION_NOT_FOUND`（404）。
- `SANDBOX`：`SANDBOX_START_FAILED`（503）、`SANDBOX_RUN_FAILED`（503）。
- `AUTH`：`AUTH_PROVIDER_UNAVAILABLE`（502）。
- `INTERNAL`：`INTERNAL_VALIDATION_FAILED`（422）、`INTERNAL_RESOURCE_MISSING`（404）、`INTERNAL_REQUEST_INVALID`（400）、`INTERNAL_METHOD_UNSUPPORTED`（405）、`INTERNAL_STATE_CONFLICT`（409）、`INTERNAL_CONFIG_MISSING`（503）、`INTERNAL_PROVIDER_FAILED`（502）、`INTERNAL_UPSTREAM_FAILED`（502）、`INTERNAL_SERVICE_DOWN`（503）。

其中 `INTERNAL_*` 为全局处理器与未迁移模板路由的兜底码，产品业务分支优先使用对应域的具体码。

## 术语表

- PascalCase / camelCase / snake_case / UPPER_SNAKE_CASE / kebab-case：见阅读背景的大小写定义。
- 错误码：`DOMAIN_REASON` 形式的稳定标识，供前端判断分支；不是用户文案。
- 领域对象：文档中描述业务概念的名称（如 `Project`），与框架自动生成的 ORM 类名（如 `Projects`）区分。
- 设计映射：文档中需求、对象与用例的对应关系，不表示测试已建立或已执行。
