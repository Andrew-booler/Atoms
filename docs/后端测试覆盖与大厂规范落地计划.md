### P2 提取三个校验纯函数（中低风险，行为等价）

- 改动：新建 `app/backend/services/studio_validation.py`：
  - `def validate_plan_payload(raw: Any) -> PlanPayload`：构造模型，缺 `steps` 或有步骤缺 `title` 时抛 `ValueError("模拟计划结构无效")`。
  - `def validate_outline_payload(raw: Any) -> OutlinePayload`：缺 `sections` 或有区域缺 `name` 时抛 `ValueError("模拟页面结构无效")`。
  - `def validate_artifact_html(html: str) -> str`：空串、缺 `<body`、缺 `</html>` 时抛 `ValueError("模拟HTML文档不完整")`，否则原样返回。
  - 三个函数依赖 `plan`/`outline` 模型，因此在 P1 之后执行。
- 路由改动：`plan`/`outline`/`artifact` 三处的内联校验块替换为 `try: payload = validate_xxx(...) except ValueError as exc: raise HTTPException(502, detail=str(exc)) from exc`。状态码与 detail 文案与现状逐字一致。
- 为什么：校验是后端单元测试的主要对象（后端-单元-09/10/11），提取后可用 pytest 直接调用，不必导入整条路由。
- 验证：现有界面集成用例中三条 502 分支行为不变（计划结构无效、页面结构无效、HTML 不完整），可用手动构造提供者失败复跑；`python -m py_compile`。
- 风险：`str(exc)` 与固定文案必须一致，否则前端提示变化。
