# 开发规范

版本：3.4｜日期：2026-11-01｜适用于当前授权实施和后续维护

## 阅读背景与必要概念

本文规定 Atoms Studio 后续获准开发时应如何组织代码，以及项目文档如何编写、自检和提交审阅。工作台的主流程是提交需求、展示计划、确认构建、保存 HTML 文档、预览并恢复历史版本。HTML 是浏览器显示页面的文字文档。本轮实施共享接入、模拟输出、串行闭环及两层测试。

本阶段要求共享账号和数据、操作串行、AI 输出使用 mock（预置成功结果或受控失败替代外部调用），未来真实 AI 仅保留替换边界，不评估输出质量。当前实现尚未全部符合这些目标。

视图（View）展示界面；控制器（Controller）协调动作与状态；模型（Model）管理业务状态。应用服务负责业务步骤，仓储（Repository）负责数据读写，输出提供者（OutputProvider）取得计划、结构和 HTML。StudioGateway 是目标请求适配对象，BuildService 是目标构建服务，不代表这些类已实现。Plan、Outline 分别描述计划和页面结构；ProjectSummary 是接口返回的项目摘要；项目、消息、历史版本是三种持久实体。事务保证其内的数据库变更全部成功或回滚；不变量是操作前后必须保持的关系，如版本必须属于所选项目。

项目字段 current_version 保存当前使用的版本序号；历史版本 id 是记录标识，version_no 是项目内序号，两者不能互换。SDK 是前端业务请求封装，HTTP 是前后端网络协议，API 是接口约定。GET 用于读取，POST 用于提交，DELETE 用于删除；200/201 是成功，404 是资源不存在，422 是字段无效，502 是提供者明确失败。Blob 是浏览器临时内容对象，不是发布链接。


## 1. 适用范围

适用于现有TypeScript/React前端、Python/FastAPI后端和PostgreSQL业务数据。最新要求不包含语言迁移，不采用Java设计。产品继续采用共享上下文、串行操作、AI模拟提供者；不新增账号、并发或真实生成质量模块。

本规范约束当前授权实施；是否满足具体规则以作者自检与执行证据为准。Amazon/AWS来源与许可必须逐文件核实，不能将第三方或本项目自定规则标成Amazon官方通用代码规范；结论见[资料来源与许可](资料来源与许可.md)。

## 2. 面向对象设计

- 单一职责：页面只渲染；控制器解释用户意图、协调状态；应用服务管理业务步骤和事务；仓储管理存取；输出提供者只返回Plan、Outline、HTML或失败。
- 封装：Project恢复版本的方法只接受属于本项目的版本；StudioVersion内容保存后不改写；不通过随意修改全局对象实现业务流程。
- 依赖倒置：Controller通过StudioGateway访问业务；BuildService依赖OutputProvider、VersionRepository等小接口，不导入具体浏览器或模型实现。
- 接口隔离：导航、剪贴板、外开窗口、持久化读写分别约定最小职责。不创建所有方法都放进去的万能服务。
- 替换原则：MockOutputProvider与未来RealOutputProvider保持同形状输入输出与失败语义；不得要求前端为具体提供者添加私有字段。
- 组合优先：控制器组合协作者；不为了“面向对象”制造继承链。React保留函数组件，在职责边界使用对象和接口，不强行转换为React类组件。
- 状态与生命周期：仅一个操作状态入口，前项结束才恢复空闲；这是串行UI约束，不是并发锁。事务随业务操作结束；Blob按60秒回收；页面卸载时停止持有浏览器展示资源，不承诺后台任务恢复。
- 不变量集中：消息和历史版本必须关联有效项目；current_version 必须对应项目内已有版本；新增历史版本、构建消息与 current_version 更新必须在同一事务中提交。HTTP字段校验不替代业务关联校验。

## 3. 命名与目录

PascalCase 表示单词首字母均大写，如 ProjectService；camelCase 表示首个单词小写、后续首字母大写，如 currentVersion；snake_case 表示小写单词用下划线连接，如 current_version；UPPER_SNAKE_CASE 表示大写单词用下划线连接，如 MAX_LENGTH。

TypeScript类与接口PascalCase、方法变量camelCase；React组件PascalCase.tsx；Python类PascalCase、模块函数snake_case、常量UPPER_SNAKE_CASE。使用有意义的Project/Version/Requirement名称，不用单字母概念缩写。

现有SQL表字段与HTTP路径保持兼容。自动生成ORM名Projects/Studio_messages/Studio_versions是代码事实，不在本轮重命名。目标领域对象使用Project/StudioMessage/StudioVersion并明确映射，不能混淆两者。

按View、Controller、应用服务、仓储和模型职责组织，不按每个小方法拆文件。源目录规则见[总架构](总架构设计.md)。正式需求、架构、开发和测试文档全部位于docs；模块设计与测试同处docs/modules；有许可的原始资料位于docs/sources。旧路径仅留索引说明，避免多份有效规范。

### 生产代码与测试代码分离

- 前端生产代码只放 `app/frontend/src/`；测试代码只放 `app/frontend/tests/`。单元测试文件名以 `.test.ts` 或 `.test.tsx` 结尾，集成测试文件名以 `.spec.ts` 结尾；不得把测试文件放进 `src/`，也不得在 `src/` 中保留仅供测试使用的导出。
- 后端生产代码分别位于 `app/backend/routers/`、`services/`、`models/`、`schemas/`、`core/`；后端测试位置设计为 `app/backend/tests/`（单元与接口集成分子目录），该目录尚未创建，创建后测试文件统一以 `test_` 开头。
- `app/backend/testing/` 是生产侧的测试装配（测试宿主与故障注入），必须与产品路由隔离，只能由测试配置启动，不得被 `main.py` 的路由自动发现纳入产品入口。
- 测试不得依赖生产库 `public` schema；后端测试只能使用名称以 `studio_test_` 开头的隔离 schema，并在每例开始前重置。

### 资源文件分离

- 静态资源（图片、图标、字体、站点文件）放 `app/frontend/public/`。
- 只有需要打包器处理、参与哈希或按模块导入的资源才放 `src/assets/`。当前项目没有该目录，不提前创建；首次出现这类资源时再建，并在变更说明中登记。
- 不得把资源文件直接放在 `src/` 根目录，也不得在组件内引用 `public/` 之外的任意路径。

### 样式与逻辑分离

- 全局设计令牌、Tailwind 指令与基础排版只放 `app/frontend/src/index.css`。
- 组件样式使用 Tailwind utility class；不为单个组件新增独立 `.css` 文件。需要复用样式时提取 class 组合或 `cn()` 组合函数，不复制大段样式。
- 内联 `style` 只允许用于运行时计算值（尺寸、进度、动态定位）；固定样式必须落在 utility class 或全局令牌。
- 空样式文件不得保留。现有 `src/App.css` 为空且未被任何模块引用，属待清理项；本轮不删除，清理需单独批准。
- 样式文件不得包含业务请求、状态管理或数据转换逻辑；逻辑文件也不得写样式常量以外的表现层细节。

### 前端分层与依赖方向

- `components/ui/` 是设计系统（shadcn 风格基础组件），不得依赖 `components/studio/` 或 `components/blog/`。
- `components/studio/`、`components/blog/` 是业务组件，只依赖 `lib/`、`hooks/`、`components/ui/`，不得反向导入页面。
- `pages/` 负责组合与路由级状态；页面不得被组件导入。
- `lib/` 放纯逻辑与业务请求封装，`api/` 放平台级接口封装，`hooks/` 放可复用状态逻辑，`contexts/` 放跨页面共享状态。
- 页面与组件不得直接 `fetch` 业务接口，必须经 `lib/` 封装。`api/settings.ts` 与 `lib/config.ts` 的 `fetch` 属平台配置能力，是明确例外，不得据此新增同类直接请求。

## 4. 请求、数据和错误

前端统一使用SDK业务适配，不绕过它直接访问API；HTTP Controller仅接受请求、校验、调用应用服务并映射结果。后端内部对象方法不作为公开API列出。

遵守现有请求/响应字段：Plan、Outline、ProjectSummary等是传输对象，三个业务实体负责保存。不得在文档中虚构fixture_id、取消接口或批准门禁。

所有异步步骤用 await 等待前一步结束后再开始，形成串行执行，执行中不开始新动作。失败结束恢复空闲，不显示虚假成功。HTML 构建请求成功时，在一次事务中保存历史版本、构建消息并更新 current_version；提交失败回滚；恢复项目当前使用的版本序号成功后读取失败如实报告部分成功。不要把一项用户操作中的两个HTTP请求声称为同一数据库原子事务。

保留404/422/提供者明确失败502契约，提交失败使用500、模拟结构无效使用502，不回传服务端凭据。错误文案用清晰中文说明哪个步骤失败，不用“多轮不传历史/旧产物”等缩写句。

## 5. 文档与测试对应

每模块包含职责、现有对象/目标类、正常步骤、状态与数据变化、失败边界、单元用例和集成用例及术语。按“模块-单元-序号”“模块-集成-序号”编号。

单元对象为类或页面，所有外部调用mock；集成真实页面/接口/测试数据库协作，仅AI边界返回固定模拟结果。Playwright Test为界面集成的主要运行框架；前端单元用 Vitest + jsdom + React Testing Library；后端单元与接口集成计划用 pytest/pytest-asyncio + httpx，标准库unittest.mock负责替身。不增加独立端到端、接口或组件层：接口集成与界面集成都归入既有「集成」层。

固定响应传入、展示、保存和预览是确定性测试；不把AI生成工程质量、语义及满足度评分重新放进用例。纯UI动作写无网络请求；保存结果用真实业务读接口复查。

## 文档编写、作者自检与验证（长期规则）

1. 作者在每篇开头说明适用范围、业务背景和必要概念。读者只需初步了解工作台及用户流程，不应靠先读另一篇文档才能理解正文。首次出现术语时就地解释，末尾术语表只补充；使用准确中文名称，不用单字母概念代号、无来源数字或压缩笔记句。
2. 先说明谁在什么条件下做什么，以及界面和数据如何变化，再列 HTTP 方法、完整路径、请求字段和响应。路径参数必须说明代表哪个记录标识。项目当前使用的版本序号与历史版本记录 id 必须区分；示例数据说明创建来源、归属与序号。
3. 用例分别写前置条件、操作步骤、请求或外部替身调用、预期响应、界面结果、持久化结果、依据与状态。纯界面动作明确“无网络请求”。单元外部调用全部模拟；集成只模拟 AI 边界。不得用页面显示代替数据库复查，不评估 AI 质量，不新增测试层级。
4. 目标、当前代码事实与待确认事项分别写明。没有实施或执行证据，不得写已实现、已通过；共享账号、串行操作、模拟输出和未来真实提供者的边界必须保留。作者只能登记自己的检查，不得虚构同事或审阅结论。
5. 作者完成修订后自检，提供修改范围、术语检查、缺项与代表性修改；结果不能只写“已完成”。不要求Mike或其他角色强制审阅。
6. 实施与验证分别登记pending、in_progress、done或blocked；验证done必须有实际检查通过证据，不能用作者自检冒充测试通过。
7. 作者检查摘要维护在[文档可读性审查记录](文档可读性审查记录.md)，实际命令、分模块结果和限制维护在[测试执行记录](测试执行记录.md)。用户已授权当前实施，不另设审阅或审批前提。

## 6. 审阅清单与采用状态

审阅未来实现时检查职责是否单一、依赖是否经接口、字段是否兼容、串行状态是否恢复、事务是否无部分成功、目标类是否真实存在、用例与动作是否对应。目录方面另查：生产代码是否只在 `src/` 或后端生产目录、测试代码是否只在 `tests/`、资源是否放 `public/`、样式是否集中在 `index.css` 与 utility class、业务组件是否反向导入页面。后端行为是否有对应的单元或接口集成用例设计。没有代码审阅或执行结果时不写“代码已经应用规范”。

当前实现新增StudioOperation与OutputProvider职责边界，保留React函数组件和FastAPI业务函数；未进行无关全局格式化或形式化类重构。有关Amazon公开仓库规则只在核实后列出适用范围和署名；不能声称已复制Amazon内部标准。

## 术语表

- Controller：协调用户动作及状态的控制器，不承担所有数据库逻辑。
- Model/View：业务状态对象及展示层，职责不同但可以使用现有React技术。
- Repository：数据存取边界，便于单元mock。
- mock：预置结果或受控失败代替外部依赖。
- 计划卡、示例提示按钮：分别展示计划操作，以及把示例文字填入输入框；旧称示例芯片不代表特殊硬件。
- 抽屉：可展开收起的边缘面板，手机已提供项目抽屉。
- 协作接口：对象之间约定的输入输出，不一定是HTTP接口。
- 不变量：操作前后必须保持成立的业务关系，如版本必须属于所选项目。
- 生产代码与测试代码分离：可执行产品逻辑与测试文件放在不同目录，测试不得混入 `src/` 或后端生产目录。
- 接口集成测试：进程内调用真实后端与真实数据库、只模拟AI边界的测试，属「集成」层的一个作用域。
- 设计映射：文档中需求、对象与用例的对应关系，不表示测试已建立或已执行。
