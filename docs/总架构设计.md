# 总架构设计

版本：3.4｜日期：2026-11-01｜范围：当前授权实施及明确的未来职责设计

## 阅读背景与必要概念

本文说明 Atoms Studio 的技术边界、对象职责、数据和执行顺序。使用者提交需求，查看计划并确认构建，系统保存 HTML 页面文档后展示预览，使用者也可恢复历史版本。本阶段要求登录用户各自的数据上下文、串行操作及模拟 AI 输出；Phase 17 起 Studio 业务路径按 `user_id` 隔离数据，未登录访问返回 401，跨用户访问返回 404。本文的目标对象不代表已创建的类。

项目保存工作空间状态；消息保存需求、计划或系统备注；历史版本保存完整 HTML。id 是记录标识，version_no 是项目内版本序号，current_version 是项目当前使用的版本序号。例如项目 101 中第一版记录 id 为 201、version_no 为 1，第二版记录 id 为 202、version_no 为 2；当前使用第二版时 current_version 为 2，恢复第一版后为 1。以上数字仅为可复现示例。

模型（Model）管理业务状态，视图（View）显示界面，控制器（Controller）接收动作并协调步骤，这种职责分离称为 MVC。应用服务（Service）执行业务步骤；仓储（Repository）封装数据库读写；工作单元（UnitOfWork）管理一次短事务的提交或回滚。事务意味着其中的数据库变更全部成功或全部撤销，不意味着两个 HTTP 请求是一个事务。实体是有持久标识的记录；值对象按内容描述数据，传输对象描述请求或响应字段，不因此新增表。ORM 是把对象映射到数据库表的技术。

接口是两方约定的输入输出；HTTP 接口是浏览器与后端之间的网络边界，内部对象方法不是网络接口。GET 读取，POST 提交，DELETE 删除；200 和 201 表示成功，404 表示资源不存在或版本不属于项目，422 表示字段校验失败，502 表示提供者明确失败。SDK 是前端请求封装，StudioGateway 是目标业务请求适配对象。mock 是以预置结果或受控失败替代外部调用；profile 是提供者配置键，balanced 是现有默认值，并不表示目标阶段调用真实模型。

Plan 是含摘要、技术说明、步骤和文件说明的计划对象；Outline 是含页面标题、区域、交互和初始数据的结构对象；HTML 是浏览器呈现页面的文字文档。OutputProvider 是返回上述输出的接口，MockOutputProvider 返回预置输出，未来 RealOutputProvider 才负责真实生成。iframe 是嵌入预览容器，srcDoc 是传入 HTML 的属性，Blob 是外开预览使用的浏览器临时内容对象。


## 1. 目标、现状和文档边界

使用者先提交需求，系统返回预置模拟计划；使用者确认后，系统依次取得模拟页面结构和 HTML 文档，保存并显示预览。使用者之后可选择历史版本恢复。Phase 17 起使用者通过邮箱/密码登录，各自数据按 `user_id` 隔离；没有用户管理后台、角色管理或租户隔离产品模块；操作必须串行，不设计并发锁。AI提供者本阶段mock，未来真实接入仅保留替换边界，不评估输出质量。

本轮保留Python/Atoms Cloud后端，不改生产 `public` 表结构及受保护平台模块。Phase 17 起 Studio 业务路由从 JWT 取得当前用户并按 `user_id` 过滤，新写入归属该用户；迁移只在本地开发库执行，生产部署需另行评审。本文中“目标类”“目标职责”是后续代码设计而非已实现事实；现有函数式React/FastAPI不会因本文更新自动成为类。

正式文档同处docs：需求、总架构、开发规范、测试策略、覆盖索引；模块设计与对应测试位于modules。内部架构文件仅保留摘要和索引，不保留另一套完整架构。

## 3. 总体结构与依赖方向

浏览器视图接收使用者动作，交给前端控制器协调。控制器通过 StudioGateway 和 SDK 发出 HTTP 请求；FastAPI 路由控制器校验输入后调用应用服务，应用服务协调实体与仓储，最终由仓储读写 PostgreSQL 数据库。

模拟构建应用服务只依赖输出提供者接口，默认MockOutputProvider；未来RealOutputProvider可实现同一契约。内部对象协作属于类设计，不列入对外API清单。

View只呈现状态和发出用户意图；Controller负责编排与状态；Model保存身份、业务状态和不变量。基础设施依赖接口边界；业务实体不导入SDK、浏览器或HTTP框架。

### MVC划分

| 划分 | 实际位置 | 目标设计 |
|---|---|---|
| Model | 三个SQLAlchemy实体及前端lib/studio.ts中的数据类型 | Project、StudioMessage、StudioVersion是持久实体；Plan、Outline、ProjectSummary等为值对象/传输对象，不额外建表 |
| View | Index、DeployPage、CloudPage及Studio展示组件 | 仍使用React函数组件，不为形式强行改成React类；只展示及派发意图，不直接保存数据 |
| 前端Controller | 当前Index事件处理和状态逻辑 | 目标StudioController组合ProjectController、PlanController、BuildController、PreviewController、VersionController；只为确有重复职责提取，不复制页面逻辑 |
| HTTP Controller | routers/studio.py中的实际路由函数 | 保留FastAPI路由为薄适配器：校验输入、调用应用服务、映射响应；不把内部方法公开为HTTP |
| 应用服务与基础设施 | 当前路由中的业务逻辑及studio_output.py | 目标ProjectService/BuildService/VersionService、仓储和提供者接口负责业务事务与替换边界 |

“Model、View、Controller”是职责划分，不要求三者拥有同名物理文件，也不把所有函数塞进一个控制器。

## 6. 面向对象原则与对象不变量

1. 单一职责：Project负责项目状态，不负责HTTP和HTML渲染；Controller不内嵌SQL；仓储不决定页面文案。
2. 封装：实体状态通过命名操作改变，Project选择有效版本、StudioVersion保存不可变内容；不把所有字段任意暴露为可写状态。
3. 依赖倒置：应用服务依赖Repository/OutputProvider契约，替换mock或未来真实提供者不影响View和HTTP形状。
4. 接口隔离：读项目、存版本、剪贴板、导航分成最小真实职责，不造一个包办所有基础设施的“大接口”。
5. 可替换：MockOutputProvider和未来RealOutputProvider返回同形状Plan/Outline/HTML或同类失败，不依赖额外业务请求字段。
6. 开闭与组合：新提供者通过实现契约替换，避免在Controller遍布模型分支；优先对象组合，不建立无业务意义的继承树。
7. 对象生命周期：Controller随页面工作区生命周期存在；请求服务及事务随一个操作创建/结束；版本快照不随预览重建而变化；Blob在约定60秒释放。
8. 不变量：消息和版本必须关联存在项目；一次成功artifact同时保存版本、构建消息和项目当前使用的版本序号；恢复只能指向同项目版本。现有数据库未定义关联外键/项目内序号唯一约束，目标规则依靠业务层明确维护，不宣称已有数据库保护。

ORM实体可保留为数据映射对象，复杂业务规则交给应用服务及领域对象；不能简单把现有路由函数改名成“类”就声称面向对象完成。当前只提取实际需要的StudioOperation和OutputProvider；其余目标类不代表已存在，不做纯形式重构。

## 7. 当前业务实体及存储结构

以下字段来自实际ORM源码，不是拟造数据库契约。created_at/updated_at由框架维护。user_id为现有实现遗留、非新版租户规则，本轮不删除字段。

| 业务实体/ORM类 | 表及字段（实际类型） | 必填及关系 |
|---|---|---|
| Project / Projects | projects：id Integer主键自增；user_id String；name String；description Text；status String；current_version Integer；preview_ready Boolean；created_at/updated_at时区DateTime | id/user_id/name非空，其他业务字段可空；是消息和版本的逻辑父实体 |
| StudioMessage / Studio_messages | studio_messages：id Integer主键自增；user_id String；project_id Integer；role String；kind String；content Text；meta Text（JSON文本）；created_at/updated_at时区DateTime | id/user_id/project_id/role/content非空；kind/meta可空；project_id索引，没有模型声明ForeignKey |
| StudioVersion / Studio_versions | studio_versions：id Integer主键自增；user_id String；project_id Integer；version_no Integer；label String；plan_summary Text；artifact_html Text；created_at/updated_at时区DateTime | id/user_id/project_id/version_no/artifact_html非空；其他业务字段可空；project_id索引，无模型声明项目序号唯一约束 |

关系：Project逻辑上有多条StudioMessage及StudioVersion；current_version指向版本序号而非版本id，也不是数据库外键。role取user/assistant/system表示对话来源，不是账号角色。meta承载plan、requirement、approved、version_id等传输信息。

Plan、Outline、RequirementDraft、PreviewDocument及各响应Summary是值对象/传输对象，不是本版本新增entity。仅3种业务entity；模板平台表不属于当前产品领域分母。

删除由Studio服务手动级联，一次提交；序号在串行场景取已有最大序号加一；恢复只改项目当前使用的版本序号并追加系统备注（kind 为 note）。预览中演示计数是浏览器运行态，不自动保存到数据库。

## 8. 前后端通信API（仅HTTP边界）

下表均为完整路径。{project_id} 表示项目记录 id，{version_id} 表示历史版本记录 id，调用时用实际标识替换花括号。沿用lib/studio.ts与routers/studio.py的公开形状。共享运行背景不在请求中引入账号参数。产品路径无登录门禁；模板通用认证仍为平台能力，不是产品入口。profile可省略，默认balanced；name为必要字段，description默认为空；完整入参校验以实际Pydantic定义为基线。

| 方法与完整路径 | 请求字段 | 成功响应 | 数据作用与模块 |
|---|---|---|---|
| GET /api/v1/studio/models | 无请求体 | 200：profiles的key/model/label/hint，default_profile | 读配置；输入/导航 |
| GET /api/v1/studio/projects | 无请求体 | 200：ProjectSummary数组 | 读共享项目，现有limit60、更新时间/id倒序；项目 |
| POST /api/v1/studio/projects | name，description可选 | 201：ProjectSummary | 新项目当前使用的版本序号0、preview_ready=false；项目 |
| GET /api/v1/studio/projects/{project_id} | 路径项目id | 200：project/messages/versions/current_artifact | messages最早400、versions倒序；项目/版本 |
| DELETE /api/v1/studio/projects/{project_id} | 路径项目id | 200：deleted=true、id | 手动删除项目消息版本；项目 |
| POST /api/v1/studio/projects/{project_id}/messages | role、content；kind默认requirement，meta可选 | 201：StudioMessage | 保存需求或其他消息；输入/构建 |
| POST /api/v1/studio/projects/{project_id}/plan | requirement，profile可选 | 200：plan/message/model | 保存预置计划；计划 |
| POST /api/v1/studio/projects/{project_id}/outline | requirement，plan_summary默认空，profile可选 | 200：outline/model | 中间结构不独立保存；构建 |
| POST /api/v1/studio/projects/{project_id}/artifact | requirement、outline，plan_summary默认空，profile可选 | 200：project/version/message/outline_title/artifact_html | 保存版本、构建消息及项目当前使用的版本序号；构建 |
| GET /api/v1/studio/versions/{version_id} | 路径版本id | 200：VersionDetail及artifact_html | 读历史文档；版本 |
| POST /api/v1/studio/projects/{project_id}/restore | version_id | 200：ProjectSummary | 修改 current_version 并保存系统恢复备注（kind 为 note）；版本 |

请求字段：name 是项目名，description 是说明，role 是消息发言方，content 是消息正文，kind 是消息类型，meta 是附加信息，requirement 是本轮需求，plan_summary 是整理后的计划文本，outline 是页面结构，version_id 是历史版本记录标识。响应字段：project 是项目摘要，messages 是消息列表，versions 是历史版本列表，current_artifact 是项目当前版本的完整 HTML；artifact_html 是历史详情或构建结果的完整 HTML；version_count 是历史版本数量，preview_ready 表示有可预览文档，status 是项目状态；deleted 表示删除成功。profiles 是配置列表，key 是配置键，model 是提供者标识，label 是显示名，hint 是说明，default_profile 是默认配置键。消息 created_at 是创建时间，项目 updated_at 是更新时间。

响应对象：ProjectSummary包含id/name/description/status/current_version/preview_ready/version_count/updated_at；StudioMessage包含id/role/kind/content/meta/created_at；VersionSummary包含id/version_no/label/created_at；VersionDetail增加project_id/plan_summary/artifact_html。

Plan包含summary、stack、steps(title/detail)、files(path/purpose)；Outline包含title、sections(name/blocks)、interactions、seed_data。固定模拟响应字段见模块用例，不把真实AI服务的内部方法列为网络接口。

404用于资源不存在/版本不属于项目，422用于请求字段校验，提供者明确失败502及detail。提供者结构无效返回502，提交异常回滚返回500，不返回成功或凭据。测试必须记录真实请求与可见结果，不擅加fixture_id、plan_id、幂等键或取消API。

## 9. 正常流程与事务边界

### 9.1 首次提交需求

1. 使用者在空闲状态输入“记录饮水”并提交。目标控制器把操作设为执行中；如果工作区尚无项目，先发送 `POST /api/v1/studio/projects`，请求包含 name（从需求整理的项目名）及可选 description。响应 201 返回新项目摘要，其中 id 是之后请求使用的项目标识。以下假定实际准备得到的 id 为 101。
2. 系统等待项目创建成功，再发送 `POST /api/v1/studio/projects/101/messages`，请求包含 role="user"、kind="requirement"、content="记录饮水"。响应 201 返回已保存需求消息。输入正文在提交前去除首尾空白；消息保存成功后前端清空输入框。
3. 系统等待消息保存成功，再发送 `POST /api/v1/studio/projects/101/plan`，请求包含 requirement="记录饮水" 和所选 profile。目标模拟提供者返回固定计划；后端保存计划消息，响应 200 返回 plan、message、model。前端展示计划卡，不自动开始构建。
4. 全部子步骤结束后恢复空闲。任何一步失败均停止后续请求；先前已经提交的数据不因此撤销，例如计划失败时已保存的需求消息仍在。

### 9.2 确认并构建

1. 使用者在空闲状态确认计划，控制器设为执行中。从计划消息 meta.requirement 读取本轮需求并去除首尾空白；把计划摘要与编号步骤整理成 plan_summary。第一轮实际文本为 `演示计划一\n\n1. 显示演示 — 使用预置页面`，其中 \n 表示换行，不是只发送“演示计划一”。
2. 系统发送 `POST /api/v1/studio/projects/101/outline`，请求包含 requirement、整理后的 plan_summary 和 profile。响应 200 返回 outline 和 model；结构字段包括页面标题、区域、交互和初始数据。此阶段不新增历史版本。
3. 结构成功后，系统发送 `POST /api/v1/studio/projects/101/artifact`，请求包含同一轮 requirement、plan_summary、刚返回的 outline 及 profile。后端取得模拟 HTML 后，在同一个短事务中插入历史版本和构建消息，更新匹配计划meta.approved/version_id及项目current_version、preview_ready，然后一起提交。
4. 响应 200 返回 project、version、message、outline_title、artifact_html。前端载入完整 artifact_html 并显示新版本，操作结束后恢复空闲。目标是调用输出提供者前结束读事务，取得输出后再开始短写事务；提交失败全部回滚，不显示保存成功。

### 9.3 第二轮追加

第一轮操作完全结束后，使用者在同一项目提交“增加备注”。系统先发送 `POST /api/v1/studio/projects/101/messages`，content 为第二轮文字；成功后发送 `POST /api/v1/studio/projects/101/plan`，requirement 为第二轮文字。使用者确认第二轮计划后，再依次发送 `POST /api/v1/studio/projects/101/outline` 与 `POST /api/v1/studio/projects/101/artifact`，各请求只使用第二轮需求、整理后的第二轮计划文本及该轮结构。

第二轮保存为新历史版本，第一版 HTML 不变。请求不携带第一轮消息列表或第一版 HTML；这只说明字段传递，不要求模拟输出理解历史或保留第一版业务功能，也不评估质量。

### 9.4 恢复历史版本

1. 前置条件是项目 101 已有两条历史版本：记录 201 的 version_no 为 1、保存第一版 HTML；记录 202 的 version_no 为 2、保存第二版 HTML。项目 current_version 为 2，工作台空闲。
2. 使用者在版本下拉框选择第一版。下拉框选中值是版本序号 1；前端据此找到历史对象，再使用该对象的记录 id 201，不能把序号 1 当成记录 id。
3. 前端发送 `POST /api/v1/studio/projects/101/restore`，请求体为 `{"version_id":201}`。后端核实记录 201 属于项目 101，在同一次事务中把 current_version 改为 1、preview_ready 改为 true 并追加系统恢复备注（消息 kind 为 note）。响应 200 返回项目摘要；历史版本的 HTML 不改写。
4. 恢复响应成功后，前端再发送 `GET /api/v1/studio/versions/201`。响应 200 返回历史版本详情，其中 artifact_html 是第一版完整文档。前端用它更新预览并把版本选择器设为第一版。
5. 当前前端立即使用恢复摘要更新activeProject和侧栏projects，并在读取完成后重新读取项目详情同步消息及版本。测试应另发 `GET /api/v1/studio/projects/101` 复查 project.current_version=1、恢复备注及 current_artifact 为第一版，而不能只看预览证明数据库结果。
6. 两次网络请求不是同一个数据库事务。如果恢复成功但读取历史详情失败，数据库已恢复第一版，前端清空旧预览并明确提示已恢复但读取失败；重试只读取，不重复恢复备注。恢复后再构建，新序号取历史最大值 2 加一得到 3，而不是当前值 1 加一，旧两版不覆盖。

## 术语表

- MVC：Model管理业务状态，View负责显示，Controller编排动作；是职责划分，不是必须三个目录。
- entity：具有持久id的业务实体；值对象按内容描述状态，传输对象定义网络响应，不自动建表。
- ORM：对象与数据库表之间的映射；现有实体类来自SQLAlchemy。
- Repository（仓储）：持久化读写接口，不负责页面逻辑。
- UnitOfWork（工作单元）：管理一个业务操作的短事务及提交/回滚边界，不是并发锁。
- DTO（传输对象）：请求或响应字段结构；正文使用完整名称。
- mock：以预置结果或受控错误代替外部调用。
- 计划卡：计划展示与确认/调整/复制的区域。
- 示例提示按钮（旧称示例芯片）：填入示例文本而不自动提交。
- 抽屉：从边缘展开收起的面板，手机已提供项目抽屉。
- profile：提供者配置键；本阶段全部使用模拟提供者。
- iframe、srcDoc、Blob：嵌入预览、传入HTML及外开用临时浏览器内容。
- TEXT：存储不限定长度文字的PostgreSQL字段类型；本项目HTML与JSON文本使用它。
